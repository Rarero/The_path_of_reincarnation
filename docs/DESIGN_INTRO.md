# 타이틀과 오프닝 설계 (DESIGN_INTRO)

최종 수정: 2026-08-06
상태: 초안 (2026-08-03 프론트엔드 확정, docs/DECISIONS.md). 2026-08-06 D12에서 허브 연결을 점검하고 반영
연동: docs/GDD.md 2장(스토리), docs/DESIGN_HUB.md(허브 5장 시작 흐름), docs/ART_STYLE.md, docs/ART_PIPELINE.md

## 1. 범위

게임 최초 진입 흐름을 정의한다. 부팅에서 첫 플레이까지의 프론트엔드다.

- 타이틀 화면: 게임 시작, 설정, 종료
- 오프닝 시퀀스: 트럭 사망부터 상행 결의까지의 도입 컷툰 (최초 1회)
- 허브 진입: 오프닝 후 저승 초입 접수청으로 인계 (상세는 docs/DESIGN_HUB.md)

컷신 최소화 원칙(GDD 2장, Dead Cells 상한)은 최초 1회 오프닝에 한해 예외로 둔다. 이후 서사는 허브 NPC 대화로 전달한다.

## 2. 씬 구조와 흐름

```
부팅 → 타이틀(main_menu) → [게임 시작]
                              ├ 오프닝 미관람 → 오프닝(intro) → 허브(hub)
                              └ 오프닝 관람   → 허브(hub)
        타이틀 → [설정] → 설정(settings_menu) → 타이틀
        타이틀 → [종료] → 종료
        허브 → [첫 런: 차사 대화 + 지도 수령] → 상행문 → 런 → (사망) → 허브
        허브 → [두번째 런부터: 조건 없음] → 상행문 → 런 → (사망) → 허브
```

- main_scene은 res://scenes/ui/main_menu.tscn (project.godot)
- 씬 전환과 페이드는 오토로드 SceneRouter가 담당 (res://autoload/scene_router.gd)
- 오프닝 관람 여부와 해금 상태는 오토로드 GameState가 보관 (res://autoload/game_state.gd)
- 첫 런 게이팅 (2026-08-06 D12): 허브에서 1막으로 나가려면 첫 런에 한해 차사 대화를 마치고 접수 관원에게 지도를 받아야 한다. 규격은 docs/DESIGN_HUB.md 5.3절

관련 씬 파일:

| 파일 | 책임 |
|---|---|
| scenes/ui/main_menu.tscn, .gd | 타이틀 화면 |
| scenes/ui/settings_menu.tscn, .gd | 설정 패널 (스텁) |
| scenes/cutscene/intro.tscn, .gd | 오프닝 컷툰 재생기 |
| scenes/hub/hub.tscn, .gd | 저승 초입 접수청 허브 |
| autoload/scene_router.gd | 씬 전환과 페이드 |
| autoload/game_state.gd | 관람 여부, 해금 플래그 |

## 3. 타이틀 화면

### 3.1 레이아웃 (기준 해상도 480x270)

해상도 표기 정정 (2026-08-06): 이 절과 4.3절이 320x180으로 적혀 있었으나 논리 해상도는 2026-08-04 결정으로 480x270이다. 실제 배치는 그 결정에서 이미 480x270 기준으로 재조정됐고(main_menu.tscn, intro.tscn) 문서 표기만 남아 있었다. 아래 여백 수치는 재조정된 화면을 기준으로 구현 세션이 확인한다.

- 배경: 전면 키비주얼 한 장 (접수청 또는 상행 실루엣 방향). 스켈레톤은 단색 플레이스홀더
- 타이틀 로고: 화면 상단 또는 좌상단. 가제 "환생길" (미정, GDD 1장). 스켈레톤은 Label
- 메뉴 버튼: 좌측 하단 세로 배치 (사용자 지정). 위에서 아래로 게임 시작, 설정, 종료
- 여백 규칙: 좌측 8px, 하단 8px 안전 여백. 저해상도라 폰트와 버튼 간격을 크게 잡는다

### 3.2 버튼과 입력

- 항목: 게임 시작, 설정, 종료
- 포커스: 진입 시 게임 시작에 포커스. 상하 이동(move_up, move_down)과 게임패드 D패드로 이동, 결정은 ui_accept(엔터, 스페이스, 게임패드 A), 마우스 클릭도 지원
- 게임패드 우선 + 키보드 지원 (GDD 11장)

### 3.3 상태 전이

- 게임 시작: GameState.intro_seen이 거짓이면 오프닝으로, 참이면 허브로. 스켈레톤 단계에서는 항상 오프닝을 보고 싶으면 설정 또는 디버그로 플래그를 초기화한다
- intro_seen 영속화 (2026-08-06 D12): 현재 intro_seen은 메모리에만 있어 게임을 껐다 켜면 오프닝을 다시 본다. G12가 신설하는 user://meta.json 스키마에 intro_seen을 함께 넣어 이 결함을 닫는다. 같은 GameState 필드이고 추가 비용이 없다 (DESIGN_HUB 5.3절)
- 설정: 설정 패널로 이동. 뒤로가기로 타이틀 복귀
- 종료: 애플리케이션 종료 (get_tree().quit())

### 3.4 설정 패널 (스텁)

- M1 스켈레톤은 자리만 잡는다. 후보 항목: 음량(마스터, 음악, 효과), 전체화면 토글, 조작 안내, 뒤로가기
- 실제 옵션 저장과 적용은 후속. 스켈레톤은 뒤로가기 버튼과 항목 라벨만 배치

### 3.5 타이틀 아트 요구

- 타이틀 배경 키비주얼 1장 (art_src/requests/013). 톤은 황혼빛 접수청 또는 위로 뻗은 상행 실루엣
- 타이틀 로고 (가제 확정 후). 스켈레톤은 텍스트로 대체
- 버튼 노멀/포커스/눌림 3상태 (UI 세트, 후속). 스켈레톤은 기본 Button 테마

## 4. 오프닝 시퀀스

### 4.1 형식

- 정적 일러스트, 미국 컷툰(패널 분할) 연출 (2026-08-03 확정). 페이지마다 1~3개 패널을 배치하고 캡션과 대사를 얹는다
- 진행: ui_accept 또는 move_up(위)으로 다음. 한 페이지에 여러 대사가 있으면 대사 단위로 넘긴 뒤 페이지 전환
- 스킵: ui_cancel(Esc, 게임패드 B). 스킵 시 GameState.intro_seen을 참으로 두고 허브로
- 강한 빛 전환: 3페이지(트럭 충돌) 끝에서 화면이 하얗게 밝아지며 4페이지로 넘어간다. 사용자가 지정한 연출. 스켈레톤은 흰 ColorRect 알파 트윈
- 종료: 마지막 페이지 후 GameState.intro_seen 참, SceneRouter로 허브 진입

### 4.2 페이지 스크립트 (7페이지)

문체는 담담한 관료적 부조리와 건조한 유머다. 이름은 판독 불가로 처리해 플레이어가 자기 이름으로 착각하게 둔다(오인 호명 장치).

1. 야근 퇴근
   - 패널 a: 야심한 사무실, 모니터 불빛 아래 홀로 남은 주인공. 패널 b: 텅 빈 야간 거리로 나오는 뒷모습
   - 캡션: "또 막차 시간이다."
   - 독백: "사무실 불은 오늘도 내가 껐다. 집에 가서 눕기만 하면 돼."

2. 횡단보도, 호명
   - 패널 a: 신호를 기다리는 주인공, 신호등이 초록으로. 패널 b: 횡단보도 절반, 뒤에서 말풍선 세 개가 점점 크게 "OO아" "OO아" "OO아" (이름 판독 불가)
   - 캡션: "누가 내 이름을 부른다."

3. 뒤돌아봄, 트럭, 강한 빛
   - 패널 a: 뒤돌아보는 얼굴 클로즈업. 패널 b: 측면에서 쏟아지는 트럭 헤드라이트, 화면 가장자리부터 하얗게
   - 효과음 표기: "빵—"
   - 전환: 페이지 끝에서 화이트 플래시 (빛이 강해지며 4페이지로)

4. 저승사자 대면
   - 패널: 눈을 뜨는 시야, 검은 갓과 검은 두루마기 차림의 저승사자가 머리를 짚고 내려다본다. 창백하고 피곤한 관원 인상, 두루마리 소지(허브 실수한 차사와 동일 인물, 채택본). 결정은 docs/DECISIONS.md 2026-08-03 저승사자 설계
   - 캡션: "눈을 뜨니 낯선 천장."
   - 저승사자: "어어, 깼네." (혼잣말) "…어, 잠깐."

5. 동명이인 오류
   - 패널: p4 시점 연장. 차사가 손에 든 문서를 보며 동명이인임을 알고 곤란해하는 표정 (검은 갓, 검은 두루마기)
   - 저승사자: "김… 아니 이…? 동명이인이네." "자네, 아직 죽을 때가 아니야."
   - 캡션: "잘못 데려온 것이다."

6. 50년 대기와 특수창고, 거부
   - 패널 a: 끝없는 민원 대기줄과 번호표, 낡은 창구. 패널 b: 먼지 쌓인 선반의 '특수창고' 팻말. 패널 c: 주인공의 굳은 표정
   - 캡션(대기줄 팻말): "여기서부터 약 300년 소요" (삼백 년 대기 강조. 이어지는 특수창고 오십 년과 대비. intro.gd queue 페이지 첫 줄로 표시)
   - 저승사자: "돌아가려면 반송 도장이 필요한데, 대기가 좀 있어." "원래 삼백 년인데 자넨 특수창고라 오십 년만 기다리면 돼."
   - 주인공: "오십 년을 어떻게 기다려."

7. 직접 상행 결의
   - 패널 a: 접수청 안쪽, 위로 뻗은 길과 멀리 염라대전 실루엣. 패널 b: 소매를 걷고 돌아서는 주인공 뒷모습
   - 주인공: "직접 가서 도장 받아 오면 되잖아."
   - 저승사자: (다급하게) "거긴 함부로 가는 데가—"
   - 캡션: "염라를 만나러." 종료 후 허브 진입
   - 허브 연결 (2026-08-06 D12): 이 끊긴 대사를 허브 첫 대화의 첫 줄("…거긴 함부로 가는 데가 아니라니까")이 잇는다. 오프닝 마지막 대사를 고칠 때는 DESIGN_HUB 5.7절 차사 첫 대화 1번 줄도 함께 고친다

### 4.3 오프닝 아트 요구

- 컷툰 패널 일러스트 세트 (art_src/requests/014). 7페이지, 패널 총합 약 12~14컷
- 스타일: docs/ART_STYLE.md 기준의 픽셀아트 일러스트. 480x270 화면에 얹히므로 패널 내부는 저해상도 가독성 우선
- 우선 컷: 트럭 헤드라이트(3), 저승사자 대면(4). 나머지는 후속
- 저승사자 도상: 검은 갓과 검은 두루마기(허브 채택본과 통일, DECISIONS 2026-08-03). 서양 사신 도상(후드, 낫) 금지

### 4.4 허브 대화와의 정합 점검 (2026-08-06 D12)

D12에서 허브 첫 대화와 지도 지급 대사를 확정하면서 오프닝 설정과 어긋나는 곳이 없는지 확인했다. 결과는 어긋남 없음이고, 확인한 연결은 넷이다.

- 동일 인물: 오프닝 저승사자 = 허브 "실수한 차사"(4~7페이지, DECISIONS 2026-08-03 채택본). 허브 첫 대화가 오프닝의 끊긴 문장을 그대로 잇는다
- 검을 주는 이유: 오프닝 5페이지의 동명이인 오류가 근거다. 허브 대사 "그래도 내 실수로 온 거니까"가 그것을 가리킨다. 물건의 출처를 "창고 정리하다 나온 것"으로 둔 것은 GDD 8장의 "관청 물품을 빼돌려 영구 업그레이드 담당"과 같은 결이다
- 말리는 태도와 조력의 공존: 오프닝에서 차사는 상행을 말리고(7페이지), 허브에서는 "포기할 때까지 기다리겠다"고 하면서 검을 준다. 모순이 아니라 규정상 말려야 하는 입장과 개인적 죄책감의 이중성이며, 검을 주는 행동이 그 이중성을 드러낸다
- 접수 관원: 오프닝 6페이지의 300년 대기줄과 50년 특수창고 창구를 지키는 인물이다. 지도를 주면서 "기록은 안 하겠소"라고 하는 것은 정식 접수를 하면 그 대기줄에 서야 하기 때문이며, 오프닝 설정을 뒤집지 않고 활용한다

## 5. 스켈레톤 데이터 구조

intro.gd는 페이지 배열을 데이터로 구동한다. 아트가 붙기 전에는 패널을 테두리 상자와 라벨로 대체한다.

페이지 스키마 (딕셔너리 배열):

- id: String, 페이지 식별자
- art: String, 패널 구성 설명 (플레이스홀더 라벨로 표시)
- lines: Array[String], 캡션과 대사. 화자 접두 사용 (예: "차사: ...", "독백: ...")
- flash_after: bool, 페이지 종료 시 화이트 플래시 여부 (3페이지 참)

데이터는 스켈레톤 단계에서 intro.gd 상단 상수로 두고, 콘텐츠가 커지면 커스텀 리소스(.tres)로 이관한다.

## 6. M 의존과 후속

- M1 스켈레톤 범위: 씬 흐름(타이틀, 오프닝, 허브 인계), 버튼 동작, 페이지 진행과 스킵, 화이트 플래시, 관람 플래그. 아트는 플레이스홀더
- G12 (허브 시작 흐름): intro_seen을 user://meta.json에 저장해 오프닝 재관람 결함을 닫는다(3.3절). 오프닝 페이지 데이터 자체는 건드리지 않는다
- 후속: 컷툰 일러스트 교체, 타이틀 배경과 로고, 설정 실동작, 사운드와 음악(국악 요소 후보, GDD 10장), 성우 또는 텍스트 연출 강화
- 가제 확정 시 타이틀 로고와 이 문서의 표기를 함께 갱신
- 대화 시스템 공유 검토(후속): 오프닝 진행 입력(ui_accept 또는 move_up)과 허브 대화 진행 입력이 같은 규약이다. intro.gd의 페이지 재생기와 G12의 대화 상자를 하나로 합칠지는 두 구현이 모두 선 뒤에 판단한다. 지금 합치면 컷툰 패널 연출과 하단 대화 상자라는 다른 표시 요구를 한 클래스가 떠안는다

# 막별 디자인 트랙 (D 시리즈)

최종 수정: 2026-07-27
상태: 트랙 보류 (2026-07-29, docs/DECISIONS.md 참고). D1~D3와 1막 요소 트랙 완료. 1막 설계는 현 수준에서 동결하고 M1 데모 구동과 판정을 우선한다. D4~D5와 후속 설계는 판정 이후 재개

## 1. 위치와 원칙

- ROADMAP의 M1 프로토타입(조작감 검증)과 병행하는 디자인 문서 트랙이다. 마일스톤 번호 체계는 변경하지 않는다
- 산출물은 전부 문서(컨셉 수준)다. 수치는 초안으로만 표기하고, 확정은 M1/M2 검증 이후로 미룬다
- M2 수직 슬라이스(1막 구현)가 D2 산출물을 소비하므로 D1, D2가 우선순위가 높다
- 디자인 원칙: 도전의식보다 재미가 최우선. 플레이어에게 좋은 경험을 많이 주는 방향으로 설계한다

### D1. 노드 맵 점수제 설계

```
노드 맵 밸런스 점수제를 설계한다. docs/RUN_STRUCTURE.md와 docs/GDD.md 4~5장을 먼저 읽어라.

배경: 무작위 생성은 전체 레벨 디자인을 해칠 수 있다. 경로 단위 점수 예산으로 무작위성을 통제한다.

내 초안:
- 각 노드에 P(Positive), N(Negative) 등급을 부여한다
- N 등급: 적과 부정적 이벤트. 마이너스 점수. 예시: 중간보스 -100, 일반 전투 -20, 부정 이벤트 -10 ~ -100
- P 등급: 보상, 상점, 긍정적 이벤트. 플러스 점수. 예시: 보물 +100, 상점 +50, 긍정 이벤트 +10 ~ +100
- 시작부터 막 보스까지 가능한 모든 경로의 합계 점수가 -50 ~ +50 범위에 들도록 생성 시 조정한다
- 점수는 예시다. 유물 등 콘텐츠가 늘면 조정한다

설계 원칙 (반드시 반영):
- 도전의식보다 재미가 최우선. 좋은 경험을 많이 주는 것이 목표다
- 좋은 보상을 얻었다고 나쁜 이벤트를 강제로 붙이는 개별 보정은 하지 않는다. 예산은 경로 단위다
- 상한 +50에 가까운 운 좋은 런의 경험도 게임의 재미로 인정한다

이 세션에서 결정할 것:
1. 방 종류별 기본 점수표 (RUN_STRUCTURE 3장의 막별 배정표 전 종류 커버)
2. 점수 검사를 기존 생성 절차(RUN_STRUCTURE 7장: 골격 -> 배정 -> 검증 -> 재배정)의 어느 단계에 넣을지
3. 기존 보장 규칙(고정층, 선택 보장, 연속 금지, 중간보스 배치 범위)과 점수 예산이 충돌할 때의 우선순위. 중간보스는 회피 가능 노드이므로 회피 경로와 조우 경로의 점수 차이 처리 방식 포함
4. 모든 경로 열거 방식 (층당 노드 2~3개, 층 6~8개라 경로 수가 작아 전수 검사 가능 여부 판단)
5. gdUnit4로 고정할 테스트 규칙 목록

산출물: RUN_STRUCTURE.md 10장 신설, DECISIONS.md 기록, PROGRESS.md 기록. 구현은 하지 않는다 (M2에서 RunMap 생성기에 반영).
```

### D2. 1막 도깨비 시장 디자인

```
1막 도깨비 시장의 상세 디자인 문서를 작성한다. docs/GDD.md(3, 7, 9장), docs/RUN_STRUCTURE.md(3장 1막, 10장 점수제), docs/DESIGN_TRACK.md를 먼저 읽어라.

막 정체성: 경제와 선택. 톤: 활기찬 밤시장, 등불 난색 팔레트.

이 세션에서 정의할 것:
1. 배경 풍: 시각 컨셉 (배경 레이어 구성, 팔레트 방향, 대표 배경 오브젝트). 아트 제작이 아니라 방향 정의다. docs/ART_PIPELINE.md의 요청서 형식으로 이어질 수 있게 쓴다
2. 맵 풍과 레벨 디자인 문법: 지형 특징 (좌판 거리, 지붕 위, 골목), 방 유형별 지형 패턴, 도깨비불 발판 활용 규칙. 점프 3.5타일 기준 준수
3. 맵 크기와 노드 수: RUN_STRUCTURE 기준(6층, 층당 노드 2~3)을 유지할지 조정할지 검토. 조정 시 근거와 함께 DECISIONS 기록
4. 적 배치: GDD 아키타입 4종(잡도깨비, 등불 도깨비, 장물아비, 씨름꾼)의 방 유형별 배치 규칙과 조합
5. 적 기믹: 아키타입별 행동 패턴 상세 (컨셉 수준, 수치 제외)
6. 중간보스 풀: 1막 중간보스 후보 5~10종의 이름, 컨셉, 기믹, 개체별 점수 가감 (RUN_STRUCTURE 10장 가감 한도 ±20과 풀 평형 규칙 준수). M2 우선 제작 2~3종 표시. 막당 1회 배치(회피 가능)와 이벤트 추가 조우 규칙은 RUN_STRUCTURE 기준 준수
7. 이벤트: 내기방 세부 (엽전 도박, 씨름판, 제한시간 내기, 중간보스 내기 상대 등장 후보), 긍정/부정 이벤트 후보 목록과 P/N 점수 지정
8. 보스: 시장 구역장 도깨비의 컨셉, 페이즈 구조, 기믹 (장물 경제, 씨름 그랩 등 막 정체성 연계)
9. 클리어 보상: 방 유형별 보상 테이블 (RUN_STRUCTURE 5장 기대치와 정합), 중간보스와 보스 보상

제약: 막당 바이옴 1~2개 스코프 규칙 준수. M2 방 템플릿 19개 산정과 연결되게 방 유형별 템플릿 아이디어를 함께 남긴다.

산출물: docs/DESIGN_ACT1.md 신설, 주요 결정은 DECISIONS.md, 완료는 PROGRESS.md 기록. GDD와 어긋나는 내용이 생기면 임의 반영하지 말고 결정으로 기록 후 GDD를 갱신한다.
```

7. 이벤트: 이벤트 노드(전용 종류, P/N 확률 표시)로 설계. 시왕의 시험(조건부 전투 도전, 제한시간 유형, 중간보스 이벤트형/소환 연계)과 뇌물 이벤트(엽전 지불로 회피와 보상) 세부, P/N 값 지정. GDD 2장 시왕 개성(구속, 시험, 뇌물)과 연결

제약: 막당 바이옴 1~2개 스코프 규칙 준수 (지옥별 구역은 바이옴이 아니라 구간 테마로 처리). 발설 조작 교란은 짧게 유지한다는 GDD 원칙 준수.

산출물: docs/DESIGN_ACT3.md 신설, 주요 결정은 DECISIONS.md, 완료는 PROGRESS.md 기록.

### D5. 통합 점검과 GDD 반영

```
막별 디자인 문서 3종의 통합 점검을 수행한다. docs/DESIGN_ACT1.md, DESIGN_ACT2.md, DESIGN_ACT3.md, docs/RUN_STRUCTURE.md(10장 점수제 포함), docs/GDD.md를 먼저 읽어라.

점검 항목:
1. 난이도 곡선: 1막에서 3막까지 적 조합, 중간보스 강도, 기믹 강도가 점증하는지. 급격한 턱이 없는지. 중간보스 풀 15~30종의 제작량이 현실적인지 (M2는 1막 2~3종, 확장은 M3)
2. 보상 경제: 엽전의 수입과 지출처가 막별로 균형인지, 권능 기대 획득 8~11개가 유지되는지, 여의주 조각 획득처가 일관적인지
3. 점수제 정합: 세 막의 이벤트와 방 점수 지정이 RUN_STRUCTURE 10장 체계와 모순 없는지, 경로 예산(막 기준치 ±50)이 막별로 성립 가능한지, 중간보스 풀과 이벤트의 개별 가감이 한도(±20)와 풀 평형(합 0)을 지키는지
4. 톤 그라데이션: 배경과 팔레트 방향이 난색 -> 한색 -> 무채색+적색 흐름을 지키는지
5. 스코프: 방 템플릿 소요량 추정을 갱신하고 (막당 18~22개, 전체 60개 내외 기준) 초과 시 절단 후보를 표시
6. M1/M2 의존성: 각 문서에서 M1 검증 결과에 따라 바뀔 항목이 명시되어 있는지

산출물: 발견한 모순은 각 DESIGN_ACT 문서에서 수정하고, GDD 3, 7, 9장에 요약 반영, 변경 이력 갱신. 주요 조정은 DECISIONS.md, 완료는 PROGRESS.md 기록.
```

## 4. 공통 규칙

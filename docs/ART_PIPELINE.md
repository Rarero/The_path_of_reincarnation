# 이미지 에셋 파이프라인

최종 수정: 2026-07-29
상태: 확정 (외부 API 중심 개정). 구축은 M2에서 수행
전제: 아트 스타일 픽셀아트. 생성은 외부 API(PixelLab) 중심 + Aseprite 수작업 마감. 로컬 ComfyUI(Windows RTX GPU) 경로는 폐기 (docs/DECISIONS.md 2026-07-29 항목)
구축 절차: docs/ART_PIPELINE_SETUP.md (Mac에서 이 가이드대로 수행)

## 1. 목표와 원칙

- 반복 가능성: 에셋 요청서(5장)에 사용 도구, 엔드포인트 또는 웹 도구명, 프롬프트, 파라미터, 스타일 레퍼런스를 기록해 재현 근거를 남긴다. PixelLab은 저장된 캐릭터(Character creator)와 저장된 오브젝트로 일관 재생성을 보장한다
- 노동 최소화: 반복 작업이 많고 AI가 구조적으로 일관성을 유지하기 어려운 영역(캐릭터 방향, 애니메이션, 타일 이음새)은 이를 전용 기능으로 해결하는 유료 서비스(PixelLab)를 쓴다. 도구 선택 기준은 "노동 절감 대비 비용"이다. 호출당 단가가 센트 수준이라 비용보다 반복 속도와 결과 품질이 실질 기준이다
- 스타일 일관성: 전역 팔레트, 해상도 규격, 스타일 레퍼런스 이미지로 산출물을 통제한다. PixelLab의 스타일 레퍼런스 기능(Bitforge, Pro 계열)과 팔레트 강제(forced palette) 파라미터를 사용한다. 개별 이미지의 품질보다 에셋 전체의 통일성을 우선한다
- 인간 검수 필수: AI 산출물은 초안이다. 최종 품질은 Aseprite 수작업 마감으로 확보한다
- 라이선스 안전: 상용 출시 전제이므로 API 서비스의 상용 이용 조건과 산출물 권리 귀속을 기록하고 관리한다 (7장)
- 엔진 친화: Godot 임포트 설정과 폴더 배치까지 파이프라인 범위에 포함한다
- 로컬 GPU 비의존: 생성은 전부 클라우드에서 수행된다. Mac 로컬에는 Python(후처리)과 Aseprite만 있으면 된다

## 2. 스타일 기준 (파이프라인 입력 규격)

파이프라인의 모든 산출물이 따라야 할 규격. M1에서 임시 그래픽으로 진행했으므로 크기 후보는 M2 첫 적용에서 확정한다.

| 항목 | 기준 | 상태 |
|---|---|---|
| 캐릭터 프레임 크기 | 32x32 또는 48x48 후보 | 미정, M2 첫 캐릭터 적용에서 확정 |
| 타일 크기 | 16x16 또는 32x32 후보 | 미정, M2 첫 타일 적용에서 확정. PixelLab 타일셋 API가 두 크기 모두 지원 |
| 전역 팔레트 | 단일 전역 팔레트 + 막별 서브 팔레트 (GDD 10장 톤 그라데이션) | 미정, M2 스타일 탐색에서 확정 |
| 팔레트 파일 형식 | .gpl (Aseprite, GIMP 호환) | 확정 |
| 아웃라인, 셰이딩 규칙 | 검정 통일 아웃라인, 4~5단계 명암, 디더링 큰 면만 등 | 초안 확정 (docs/ART_STYLE.md, 2026-07-29). 최종은 M2 S0 선별 |

## 3. 파이프라인 단계

5단계 구조를 유지한다. 생성 주체가 로컬 GPU에서 외부 API로 바뀌어도 "생성물은 초안이고 후처리와 수작업 마감을 거쳐 엔진에 들어간다"는 흐름 자체는 동일하기 때문이다. S1에서 S4는 에셋 1건마다 반복한다.

```
S0 스타일 정의 -> S1 생성 -> S2 후처리 -> S3 수작업 마감 -> S4 임포트, 검증
   (1회 + 갱신)  (PixelLab)   (스크립트)     (Aseprite)        (Godot)
```

### S0 스타일 정의 (프로젝트 초기 1회, 이후 갱신)

- 스타일 가이드(docs/ART_STYLE.md)와 전역 팔레트(.gpl)를 작성한다
- 스타일 고정용 레퍼런스 이미지 세트를 만든다. PixelLab에서 초기 탐색 생성을 반복해 채택본을 레퍼런스로 승격하는 방식이다. 구 계획의 LoRA 학습은 로컬 GPU 폐기와 함께 폐지한다. PixelLab의 스타일 레퍼런스 입력이 같은 역할을 대신한다
- 레퍼런스 세트는 art_src/style_refs/에 커밋해 모든 생성 요청에 재사용한다

### S1 생성 (PixelLab, 웹 UI 또는 API)

에셋 유형별로 PixelLab의 전용 도구를 쓴다. 4장 표가 유형별 선택 기준이다.

반입 절차 (2026-08-05 신설): 다운로드는 프로젝트 루트 pixellab/ (받은편함)에 그대로 넣는다. Cowork가 정체를 확인해 규칙 이름으로 개명하고 art_src/generated/pixellab/의 분류 폴더로 옮긴 뒤, S2 후처리와 인게임 반영까지 진행한다. 세부 규칙은 pixellab/README.md와 art_src/generated/pixellab/README.md를 따른다.

- 캐릭터, 적 스프라이트: Character creator에 캐릭터를 생성, 저장한다. 이후 방향, 상태(포즈, 의상), 애니메이션(걷기, 공격 등)을 저장된 캐릭터 기준으로 생성해 방향과 프레임 간 일관성을 서비스가 보장한다. 본 게임은 사이드뷰이므로 실사용 방향은 좌우 중심이고, 8방향 생성은 필요한 경우에만 쓴다
- 타일셋: 사이드스크롤러 타일셋 도구(create-tileset-sidescroller)를 쓴다. 플랫포머용 이음새 연결 타일과 투명 배경 플랫폼을 생성한다. 16x16, 32x32 모두 지원한다
- UI: UI 전용 도구(Create UI elements)로 버튼, 체력바, 슬롯, 메뉴를 생성한다. 팔레트와 컨셉 이미지 입력을 지원한다
- 컨셉아트, 배경, 오브젝트: 범용 이미지 생성(Pixflux, Pixen, 스타일 참조가 필요하면 Bitforge 또는 Pro 계열)을 쓴다. 맵 오브젝트는 맵 일부를 보여주고 생성하는 전용 도구(map-objects)가 있다
- 접근 방식: 웹 UI가 기본이다 (구독 범위 내 반복, 코드 불필요). 동종 에셋을 대량 반복할 때만 API(Python)로 자동화한다. 절차는 docs/ART_PIPELINE_SETUP.md
- 보조 후보: Retro Diffusion API (타일셋 호출당 약 0.10달러, 이미지 0.015에서 0.18달러). PixelLab 타일 품질이 기준 미달일 때 비교 대상으로만 유지한다. 초기 구독이나 셋업은 하지 않는다

### S2 후처리 (Python 스크립트, 자동화)

- 처리 항목: 팔레트 양자화(전역 팔레트 강제), 알파 이진화, 다운스케일(고해상도 원본에만), 스프라이트 시트 조립(추후), 파일명 규칙 적용
- 위치: tools/pipeline/postprocess.py. Cowork 환경에서 작성과 검증이 가능하다
- 외부 API 출력 대응 완료 (2026-07-29): PixelLab 출력은 이미 목표 해상도의 픽셀아트이므로 다운스케일 없이 팔레트 양자화와 알파 이진화만 적용한다. --scale, --size를 생략하면 크기를 유지한다
- 입력과 출력 경로, 옵션은 에셋 요청서(5장)에 기록한다

### S3 수작업 마감 (Aseprite)

- 클린업, 실루엣 보정, 히트박스 기준 정렬, 타일 이음새 보정
- 캐릭터 애니메이션은 PixelLab이 대부분 생성하므로 수작업은 프레임 보정과 이펙트 합성 위주다. 프레임 자체 제작은 산출물이 기준 미달일 때만 예외적으로 수행한다
- .ase 원본을 art_src/work/에 보관하고, Aseprite CLI로 PNG와 시트 내보내기를 자동화한다

### S4 임포트, 검증 (Godot)

- 프로젝트 기본 임포트 설정: texture filter nearest, mipmap off
- 배치: 최종 PNG는 assets/sprites/ 아래 (CONVENTIONS.md 폴더 구조 준수)
- 검증 체크리스트: 인게임 크기 확인, 팔레트 일치, 애니메이션 재생, 타일 이음새, 픽셀 왜곡 여부
- 같은 Mac에서 Godot 에디터가 열리므로 임포트 확인 루프가 즉시 돈다

## 4. 에셋 유형별 전략

전 유형이 PixelLab 단일 서비스로 통합됐다 (2026-07-29). 유형별로 쓰는 도구와 수작업 비중이 다르다.

| 유형 | AI 기여도 | PixelLab 도구 | 전략 |
|---|---|---|---|
| 캐릭터, 적 스프라이트 | 높음 | Character creator, 방향 생성, 애니메이션 | 캐릭터를 저장해 두고 방향과 애니메이션을 저장된 캐릭터 기준으로 생성. 일관성을 서비스가 보장. 수작업은 보정 위주 (2026-07-27 결정 유지) |
| 타일셋, 배경 | 중간에서 높음 | 사이드스크롤러 타일셋, 범용 생성 | 전용 API가 이음새 연결을 처리해 기존 로컬 대비 수작업이 줄어든다. 잔여 이음새는 Aseprite 보정 (2026-07-29 확정) |
| UI, 아이콘 | 높음 | Create UI elements, 범용 생성 | UI 전용 도구 + 팔레트 강제. 수량이 많은 영역이라 배치 생성 후 S2 자동 후처리 (2026-07-29 확정) |
| 컨셉아트, 키비주얼 | 높음 | 범용 생성 (Pixflux, Pro) | 컨셉 탐색은 저비용 반복. 키비주얼은 PixelLab 상한(512x512)을 넘는 해상도가 필요하면 별도 도구를 그때 검토 |

## 5. 반복 작업 구조 (재현성)

### 에셋 요청서

에셋 1건 = 요청서 1건. art_src/requests/ 아래 마크다운으로 작성한다 (request_template.md 사용).

기록 항목: 에셋 이름, 유형, 크기, 팔레트, 사용 도구(웹 도구명 또는 API 엔드포인트), 프롬프트, 스타일 레퍼런스, 저장된 캐릭터/오브젝트 ID, 후처리 명령, 상태(생성, 마감, 임포트 완료)

### 폴더 구조

```
pixellab/             # PixelLab 받은편함. 미분류 다운로드가 들어온다 (git 제외, .gdignore)
art_src/              # 원본과 중간물. .gdignore로 Godot 임포트 제외
  requests/           # 에셋 요청서 (커밋 대상)
  generated/          # S1 원본 출력 (git 제외)
    pixellab/         # PixelLab 원본 분류 보관 (git 제외)
      grids/          # 생성 원본 그리드, 밴드, 타일셋 시트
      objects/        # 48px 단품 오브젝트
      chars/          # 캐릭터 Export (zip과 해제본)
      anims/          # 애니메이션 프레임 시트
      previews/       # 판정용 미리보기
      ui/             # UI 생성물
      archive/        # 기각본, 구버전, 중복 재다운로드
  style_refs/         # S0 스타일 레퍼런스 세트 (커밋 대상)
  work/               # .ase 작업 파일 (커밋 대상)
  palettes/           # .gpl 팔레트 (커밋 대상)
tools/
  pipeline/           # S2 후처리, 조립, 프리비즈 스크립트 (커밋 대상)
assets/sprites/       # 최종 PNG. Godot 참조 (커밋 대상)
```

tools/comfyui/workflows/는 로컬 경로 폐기로 용도가 사라졌다. 빈 폴더는 정리한다.

### git 관리 기준

- 커밋 대상: 요청서, 스타일 레퍼런스, 팔레트, 스크립트, .ase 작업 파일, 최종 PNG
- 제외 대상: S1 원본 출력 등 대용량 중간물(.gitignore), PixelLab API 키(.env로 관리, 절대 커밋 금지. .gitignore 등록 완료)
- 파일명은 CONVENTIONS.md 규칙(영문 소문자 snake_case) 준수. 예: player_idle_01.png, tile_market_ground.png

## 6. 도구 스택과 비용 (2026-07-29 조사 기준)

| 도구 | 역할 | 비용 | 비고 |
|---|---|---|---|
| PixelLab 구독 | S1 생성 전체 (웹 UI, Aseprite 플러그인) | Tier 2(Pixel Artisan) 월 24달러, 연속 구독 할인 시 22달러 (2026-07-30 Tier 1에서 상향, DECISIONS) | 이미지 최대 512x512, 월 5,000 generations, 동시 10작업. 대형 오브젝트(아레나, 보스) 대응 |

| 캐릭터 선행 테스트 | 8방향 + 애니메이션 수회 | 약 2 |
| 합계 | | 약 57~61 (월평균 약 29~31. Tier 2 상향 반영) |

웹 UI 사용분은 구독 생성 풀에 포함되므로 실제 종량 지출은 API 자동화를 쓸 때만 발생한다. 상한 관리: 월 종량 지출이 구독료를 넘으면 사용 패턴을 재검토한다.

## 7. 라이선스와 상용 이용 유의사항

- Steam은 AI 생성 콘텐츠 사용 시 스토어 제출 단계에서 공개(disclosure)를 요구한다. 사용 도구와 범위를 기록해 두었다가 제출 시 명시한다. 현 시점 대상: PixelLab (필요 시 Retro Diffusion 추가)
- PixelLab: 구독 시작 시 이용약관(Terms of Service)에서 상용 이용 범위와 산출물 권리 귀속을 확인하고 결과를 ART_PIPELINE_SETUP.md 기록란에 남긴다 (1회)
- 미확인 서비스는 양산에 투입하지 않는다

## 8. 로드맵 연계

| 마일스톤 | 파이프라인 작업 |
|---|---|
| M1 | 완료 (임시 그래픽 사용, 파이프라인 미개입) |
| M2 | 구축: PixelLab 구독 시작(구축 착수 즉시), S0 스타일 탐색과 팔레트 확정, 타일과 UI부터 적용 (ROADMAP M2 항목), S2 스크립트 실사용 검증, 캐릭터 경로 선행 테스트 1종 |
| M3 | 실제 아트 적용: 캐릭터, 적 스프라이트 본격 생산 (Character creator 기반) |

구독 시작 시점: M2 파이프라인 구축 착수와 동시 (ART_PIPELINE_SETUP.md 수행 시점). 그 전에는 무료 등급(200x200)으로 스타일 탐색을 먼저 시작할 수 있다.

## 9. 리스크와 완화

| 리스크 | 완화 |
|---|---|
| 단일 서비스(PixelLab) 종속 | 원본과 중간물을 로컬(art_src/generated/pixellab/)에 보관해 서비스 중단 시에도 기존 산출물 유지. 요청서에 프롬프트와 파라미터가 남아 타 도구 재현 가능. 보조 후보(Retro Diffusion) 유지. 최후 수단은 Aseprite 수작업 |
| 스타일 드리프트 | 스타일 레퍼런스 세트 고정(S0), 팔레트 강제 파라미터, S2 팔레트 양자화, 캐릭터와 오브젝트 저장 후 재사용 |
| 타일, UI 품질이 기준 미달 | 웹 UI로 소량 검증 후 채택 (M2 첫 적용에서 판단). 미달 시 Retro Diffusion 비교, 그래도 미달이면 해당 유형만 수작업 비중 상향 |
| 구독 지속 비용 | Tier 1로 시작, 실사용 기록으로 판단. M2 예상 비용은 월 20달러 미만 (6장) |
| 라이선스, Steam 심사 리스크 | 이용약관 확인과 기록, disclosure 준비 |
| 파이프라인 과투자 | 로컬 GPU 구축이 사라져 셋업이 반나절 이하로 줄었다. 여전히 UI, 타일 등 M2 소비처가 있는 영역부터 적용한다 |

## 0. 이 문서의 범위

- 대상: 1막 도깨비 시장의 일반 전투 적(잡몹). 중간보스는 docs/act1/MIDBOSS.md, 보스는 docs/act1/BOSS.md에서 별도로 다룬다
- 목적: 1막 일반 적을 구현 직전 수준으로 정의한다. 상태 머신, 공격 패턴 타이밍, 대응 윈도우, 감지와 어그로, 데스매치 반영, 처치 보상, 배치와 조합, Godot 구현 노트를 포함한다
- 아트 제작이 아니라 일반 설계다. 조형은 판별 신호(실루엣, 색, 모션) 수준까지만 정의하고, 픽셀아트 스펙은 docs/ART_PIPELINE.md와 아트 세션에서 다룬다
- 확정 라인업 5종 (짐꾼 도깨비는 2026-08-10 보류, 5.6 참고)은 풀 상세를 작성한다 (2026-08-06 D11에서 짐꾼 도깨비를 6번째로 채택). 도깨비 종류 배분과 추가 후보는 8장에서 정리한다

### 수치 표기 원칙

- 모든 수치는 초안이다. 확정 시점(M1 체감 확인, M2 밸런싱)을 각 항목에 명시한다
- 스탯은 상대 등급으로 표기한다. 플레이어 기준을 1.0으로 두고 소(S), 중(M), 대(L)로 등급화한다. 절대 수치는 M1 전투 프로토타입에서 확정한다
- 공격 타이밍은 60fps 기준 프레임과 초를 병기한다. 프레임은 애니메이션 타이밍의 목표치이며 전부 export 변수로 노출해 에디터에서 튜닝한다 (docs/PROTOTYPE.md 8장)
- 밸런스 수치는 코드가 아니라 커스텀 리소스(.tres)에 둔다 (docs/CONVENTIONS.md 데이터 규칙). 9장 구현 노트 참조

## 1. 설계 공통 원칙

- 재미 최우선: 도전의식보다 좋은 경험을 우선한다 (docs/DESIGN_TRACK.md 원칙). 1막은 런에서 가장 많이 반복하는 워밍업 막이므로 부담은 낮게, 학습 곡선은 완만하게 설계한다
- 예비동작 명확: 모든 공격은 읽을 수 있는 예비동작을 가진다. 이지선다 심리전보다 반응 가능성을 우선한다
- 순차 행동: 여러 마리가 동시에 공격하지 않고 시차를 둔다. 다굴 스트레스를 구조적으로 통제한다
- 대응 다양성: 각 적은 이동, 점프, 대시, 근접, 원거리 중 서로 다른 대응을 요구하도록 역할을 분리한다. 하나의 최적해로 모든 적이 처리되지 않게 한다
- 문화 고증: 오니 유래 요소(뿔, 호피 무늬, 가시 철퇴, 단색 피부 옥졸형, 인간을 잡아먹는 지옥 괴물)를 배제한다. 사람 형상 기반의 원형 도깨비, 도구 변신, 불덩이, 씨름과 내기 성격을 반영한다 (reference/act1_dokkaebi/01 6장 체크리스트)
- 경제 정체성 연계: 적은 처치 시 엽전과 드랍으로 1막 경제 순환에 기여한다 (DESIGN_ACT1 10장). 장물아비는 이 순환을 교란하는 역할로 정체성을 강화한다

## 2. 공통 스탯 프레임

플레이어 기준 상대 등급. 절대 수치는 M1 확정.

| 스탯 | 정의 | 등급 표기 |
|---|---|---|
| 체력(HP) | 처치까지 필요한 피해량 | S(빠른 처치), M(기본), L(단단함) |
| 이동속도 | 플레이어 지상 이동 대비 | S(느림), M(비슷), L(빠름) |
| 접촉/공격력 | 1회 피격 시 플레이어 손실 | S(경미), M(주의), L(치명) |
| 감지 범위 | 어그로가 걸리는 거리 | S(근접), M(중간), L(원거리) |
| 피격 경직 | 플레이어 공격에 밀리는 정도 | 약(경직 큼), 중, 강(슈퍼아머 구간 존재) |

- 접촉 피해와 공격 피해는 구분한다. 접촉 피해는 몸에 닿을 때, 공격 피해는 공격 판정(히트박스)에 맞을 때다. 대부분의 적은 접촉 피해 S, 공격 피해가 본체다
- 처치 난이도는 HP만이 아니라 공격 빈도와 위협 범위의 조합으로 조절한다. 워밍업 막이므로 개별 HP는 낮게 두고, 밀도와 조합으로 난이도를 만든다 (6장 배치)

### HP 등급의 시간 앵커 (2026-07-27 신설)

상대 등급만으로는 전투방 체류 60초 기준(RUN_STRUCTURE 4장)을 검증할 수 없다. 등급을 기본 무기 기준 처치 소요 시간으로 앵커한다. 절대 수치는 M1 확정이지만 이 앵커가 있으면 그 전에도 예산 계산이 성립한다.

| 등급 | 기본 무기(총검 근접) 기준 | 처치 소요 시간 |
|---|---|---|
| S | 3타 | 약 2.5초 |
| M | 5타 | 약 4초 |
| L | 12타 | 약 10초 |

- 기준 무기는 M1 검증 무기인 기본 총과 총검이다 (docs/PROTOTYPE.md). 무기와 권능이 붙으면 짧아진다
- 이 앵커는 시간 예산 산정용이며, 실제 HP 절대값은 M1 전투 프로토타입 체감 후 확정한다

### 위협 포인트 예산제 (2026-07-27 신설)

방당 적 수 상한을 개체 수가 아니라 위협 포인트(pt)의 합으로 정한다. 6장 조합 금지 매트릭스의 상당 부분을 이 예산이 대체한다.

| 개체 | 위협 pt | 산정 근거 |
|---|---|---|
| 잡도깨비 | 1.0 | 기준값. 단일 근접, 순차 공격 대상 |
| 달걀도깨비 | 0.5 | 회피 대상 해저드. 처치 대상이 아니다 |
| 등불 도깨비 | 1.5 | 원거리라 위치 제약을 걸고 접근 비용이 든다 |
| 장물아비 | 2.0 | 피격 시 이중 손실(체력과 엽전)이라 주의 자원 소모가 크다 |
| 씨름꾼 | 4.0 | 그랩이 플레이어 상태를 탈취한다. 주의 자원 최대 |
| 짐꾼 도깨비 (보류, 5.6) | 2.0 | 2026-08-10 라인업 제외. 재합류 시 이 값으로 되돌린다. 현재 spawn_catalog 에 없다 |

- 방 예산: 지도 진행도가 정한다. 시작 3pt에서 보스 10pt까지 보간하고 0.5 단위로 반올림하며, 생기 고갈 단계마다 +1pt가 붙는다 (2026-08-06 자유 이동 전환. RUN_STRUCTURE 11.7, 이 문서 6장). 종전의 층별 표(L1 3pt, L2와 L4 6pt, L8 10pt)는 폐기했다. 웨이브가 둘이면 웨이브별 상한은 방 예산의 60퍼센트를 넘지 않는다
- 예산제가 대체하는 금지 규칙: 씨름꾼과 장물아비 동시 배치(4.0 + 2.0 = 6.0)는 L8에서만 성립하고 그때도 다른 적을 4pt 이하로 눌러야 한다. 별도 금지 항목 없이 자연히 걸러지므로 저밀도 상황에서는 허용되어 조합 폭이 늘어난다
- 예산제로 대체하지 않고 남기는 하드 금지는 넷이다 (2026-08-10 짐꾼 보류로 다섯에서 줄었다). 배치로 막는 셋은 달걀도깨비 밀집(가독성), 씨름꾼 2 이상 동일 웨이브(그랩 중첩), 장물아비 2 이상 방당(이중 손실 중첩), 짐꾼 도깨비 2 이상 동일 웨이브(정면 가드 중첩으로 회피로가 봉쇄될 수 있다, 2026-08-06 D11 신설)다. 나머지 하나인 잡도깨비 다수 동시 공격은 행동 규칙이라 EnemyBase 쪽 책임이다 (6장 참고)
- 예산과 60초 기준의 연결: 6pt 방은 HP 등급 시간 앵커로 환산해 처치 시간 합이 약 20초이고, 나머지 40초가 이동과 회피와 웨이브 전환에 쓰인다는 가정이다. M1 전투 프로토타입에서 이 가정을 검증한다
- 데스매치 발동 시간을 방 예산에 연동한다. 6pt 이하는 90초, 8pt 이상은 110초다. 2026-08-05 G8 세션에서 scenes/levels/room.gd에 이미 구현됐다(DENSE_BUDGET=8.0, DENSE_RAGE_THRESHOLD=110.0, 결정 2). 이번 세션(D11)에서 이 문서와 구현이 일치함을 확인해 확정으로 승격한다. 상한과 곡선(RageTimer.enemy_cap, player_cap)은 여전히 M1 체감 확인 대상
- pt 값은 코드 상수가 아니라 EnemyStats 리소스의 필드로 둔다. scripts/data/enemy_stats.gd에 `threat_pt` 필드로 이미 구현됐다(2026-08-05 G8, DECISIONS.md 결정 3). 개체 추가 시 코드 수정 없이 확장된다

## 3. 공통 상태 머신

모든 일반 적은 아래 상태 집합을 공유한다. 개체별 특이 상태는 각 절에서 추가한다.

| 상태 | 설명 | 주 전이 조건 |
|---|---|---|
| SPAWN | 등장 연출. 짧은 무적, 입력 불가 | 연출 종료 후 IDLE 또는 ALERT |
| IDLE / PATROL | 비전투. 정지 또는 순찰 | 플레이어 감지 시 ALERT |
| ALERT | 감지 직후 인지 지연. 방향 전환과 짧은 반응 딜레이 | 지연 종료 후 APPROACH 또는 REPOSITION |
| APPROACH | 플레이어에게 접근 (근접형) | 공격 범위 진입 시 WINDUP |
| REPOSITION | 거리 유지 (원거리형) | 사거리 확보 시 WINDUP, 근접당하면 이탈 |
| WINDUP | 공격 예비동작. 예고 신호 표시 | 예비 시간 종료 시 ATTACK |
| ATTACK | 공격 판정 활성 | 판정 종료 시 RECOVER |
| RECOVER | 후딜레이. 반격 윈도우 | 후딜 종료 시 APPROACH/REPOSITION |
| STAGGER | 피격 경직. 넉백 | 경직 시간 종료 후 이전 상태 복귀 |
| STUN | 특수 경직 (예: 돌진 충돌). STAGGER보다 김, 큰 반격 윈도우 | 스턴 시간 종료 |
| DEATH | 처치. 드랍 생성 후 소멸 | - |

- 확정 5종은 모두 위 상태 집합으로 성립한다. 도주 상태(FLEE)를 쓰는 개체는 없다. 이벤트 장물아비 소굴의 도주와 추격은 소굴 전용 변형이며 그 문서에서 정의한다 (docs/act1/EVENTS.md 부록 A)

### 감지와 어그로 규칙

- 감지: 전방 우선 시야(정면 넓은 원뿔) + 근접 전방향 반경. 등 뒤 접근은 근접 반경에 들어야 감지된다. 스텔스 접근(감투, 등 뒤 대시)에 보상을 준다
- 인지 지연: 감지 후 ALERT에서 짧은 지연(초안 0.2~0.4초, M1 확정)을 둔다. 선제 공격의 가치를 만든다
- 어그로 유지와 해제: 시야에서 벗어나도 일정 시간(초안 3초, M1 확정) 어그로를 유지한다. 이후 마지막 목격 지점으로 이동 후 미발견 시 IDLE 복귀
- 무리 공유: 한 마리가 감지해도 자동 전체 공유는 하지 않는다. 시야가 겹치는 개체만 연쇄 반응한다. 방 전체 동시 각성으로 인한 다굴을 막는다 (순차 행동 원칙)
- 감투 은신 중에는 어그로가 해제된다 (DESIGN_ACT1 3장). 피격 시 해제

### 피격 반응 규칙

- 경직(STAGGER): 플레이어 근접타에 짧은 경직과 넉백. 원거리형은 경직이 커서 접근 압박에 취약하고, 근접형은 경직이 작다
- 슈퍼아머: 씨름꾼의 그랩 예비동작 등 지정 구간에만 부여한다. 남용하면 예비동작 읽기 학습이 무의미해지므로 최소화한다
- 처치 연출: 도깨비는 정체가 드러나면 헌 도구로 되돌아간다는 원형(reference 01, 02)을 처치 연출로 활용한다. 소멸 시 빗자루, 부지깽이, 절굿공이 등으로 흩어지는 이펙트

### 데스매치(생기 몰림) 오버레이

RUN_STRUCTURE 9장 규칙을 적 단위로 구체화한다.

- 데스매치는 상태가 아니라 전 상태에 겹치는 오버레이 플래그(enraged)다. 전투방 타이머 초과 시 방 안 모든 적에 일괄 적용된다
- 효과: 적 공격력에 배율을 적용한다. 시작 배율을 1.25배로 통일한다(2026-08-06 D11. 기존 이 문서는 1.2배, scripts/systems/rage_timer.gd 구현은 enemy_step=0.25로 발동 즉시 1.25배였다. 코드를 구현 근거로 삼아 문서를 1.25배로 정정했다. 코드 변경 없음). 이후 10초 단계마다 0.25배씩 추가되며 상한(2.5배)까지 오른다. 플레이어 공격력도 함께 상승하되(10초 단계마다 0.10배, 상한 1.5배) 적 상승률이 더 가파르다 (RUN_STRUCTURE 9장). 상승 곡선 자체(step_interval, enemy_step/player_step, 상한)는 여전히 M1 체감 확인 후 최종 확정
- 이동속도와 공격 쿨다운은 기본적으로 바꾸지 않는다. 버티기 악용 차단의 목적은 공격력 상승으로 달성하며, 속도까지 올리면 반응 가능성(예비동작 읽기)이 훼손된다
- 연출: 도깨비 눈빛이 적색으로 변한다 (DESIGN_ACT1 6장 공통). 방의 도깨비불과 등불도 적색으로 전환된다 (DESIGN_ACT1 3장 색 신호). 적색은 평시 금지색이라 신호가 명확하다 (DESIGN_ACT1 2장 팔레트)
- 발동은 실패가 아니라 분위기 전환으로 표현한다 (RUN_STRUCTURE 9장). 경고 연출을 선행한다

### 5.1 잡도깨비 (근접) - M1 우선

정체성과 역할

- 1막의 기본 얼굴. 수가 많고 개체는 약하다. 플레이어의 기본 전투 리듬(회피와 반격)을 학습시키는 유닛
- 역할: 지속적인 근접 압박. 단독 위협은 낮고 밀도와 조합으로 난이도를 만든다. 돌진 속성은 씨름꾼(5.4)으로 이관해 잡도깨비를 순수 근접으로 단순화했다 (2026-07-24 조정). 이후 예고형 돌진을 특수행동으로 재도입한다: 돌진 전 웅크림 예비(부위 하이라이트 + 예고음)를 두고 속도와 발동을 낮춰 반응 가능하게 한다. 씨름꾼의 도약 돌진(공간 제압)과 달리 짧고 낮은 지상 돌진이다 (2026-08-04, docs/DECISIONS.md)
- 돌진 수치 확정 (2026-08-06, D11): 접근 이동속도를 낮추고(76 -> 60px/s), 웅크림 예비를 0프레임에서 20f(0.33s)로 신설하고, 그만큼 돌진 자체의 배율(2.2 -> 2.9)과 지속(0.55s -> 0.70s)을 올려 돌진 거리를 약 92px에서 약 122px로 늘렸다. 세 변경의 상쇄 여부 검산은 아래 "수치 검산" 참고
- 근접 패턴 구현 완료 (2026-08-06, D11 2차): 근접 휘두르기와 연속 할퀴기를 AttackPattern 리소스로 구현했다. D11 1차의 "M2로 미룬다" 판단을 같은 날 뒤집은 것이며, 미루기의 전제 셋 중 결정적인 하나가 해소됐기 때문이다. AttackPattern 리소스를 함께 신설해(9장) 분기 하드코딩 없이 데이터로 패턴을 넣을 수 있게 됐다. 나머지 두 전제는 이렇게 처리했다. 개체 복잡도는 패턴 선택을 무작위가 아닌 순번으로 두어 읽기 난이도를 올리지 않았고, 미생성 클립은 예비 구간에 정지 + 밝기 점멸을 임시로 쓰고 실제 클립을 A8로 넘겼다 (돌진 예비와 같은 처리)
- 패턴 선택 규칙 (2026-08-06, D11 2차): stats.attack_range(30px)가 근접 진입 게이트이고 그 안에서 패턴별 range_px가 다시 갈린다. 연속 할퀴기 22px, 근접 휘두르기 30px이라 밀착 구간에서는 둘 다 후보가 되어 순번으로 번갈아 나오고, 22~30px 구간에서는 사거리가 긴 휘두르기만 나온다. 무작위가 아니라 순번인 것은 의도다. 이지선다 심리전보다 반응 가능성을 우선하는 1장 원칙을 따른다. attack_range는 D11 1차 시점에 스크립트가 참조조차 하지 않던 값이었고 이 규칙으로 실제 의미를 갖게 됐다
- 접근과 돌진 발동 구간 (2026-08-06, D11 2차): 근접 사거리 밖 30~132px에서는 예고형 돌진을, 그보다 멀면 걸어서 접근한다. 돌진 발동 상한(charge_trigger_range 132px)은 돌진 도달 거리(약 122px)보다 조금 넓게 잡은 값이다. 감지 범위 300px 전체에서 돌진하던 기존 구현은 대부분 닿지 않는 헛돌진이 되어 예고 학습이 아니라 소음이었다. 접근 구간에는 속도를 사인파로 흔드는 처리를 넣어 5.1의 지그재그(어수룩한 이동)를 대신한다. 지상 이동만 가능한 개체라 좌우 지그재그가 성립하지 않아 속도 변조로 번역했다

수치 검산 (2026-08-06, D11)

- 세 변경이 상쇄되는지 방 폭 960px과 플레이어 대시(현재 구현 기준 490px/s x 0.18s = 88px, 전체 구간 무적)로 검산했다. 사용자가 제시한 기준(420px/s, 0.14초)은 2026-08-04 화면 확대 이후 player.gd에서 490px/s, 0.18s로 조정된 값으로 갱신됐다(코드 확인, 거리는 약 88px로 거의 동일하게 유지됨). 이하 검산은 실제 구현값 기준이다
- 접근이 지루해지지 않는가: 이동속도 76 -> 60px/s는 약 21% 감소다. 960px 방을 가로지르는 데 12.6초에서 16초로 늘지만, 감지 후에는 곧바로 웅크림으로 전환되므로 순찰 구간 자체가 플레이 시간에서 차지하는 비중은 작다. 체감상 크게 느려 보이지 않도록 배율 상향으로 돌진 순간의 속도(구 167.2px/s, 신 60 x 2.9 = 174px/s)는 오히려 유지하거나 소폭 올렸다. 접근은 느려지되 위협의 정점(돌진)은 죽지 않는다
- 좁은 방에서 회피 불가가 되지 않는가: 웅크림 20f(0.33s)는 반응 임계 14f(0.23s)의 1.43배 여유가 있다. 플레이어가 예비를 보고 즉시 대시하면 0.18초 만에 88px를 무적으로 벗어나고, 웅크림이 끝나는 0.33초까지 남는 0.15초 동안 도보로도 약 25px 추가 이탈이 가능해 총 113px 안팎을 확보한다. 이는 돌진 거리 122px에 거의 맞먹어 회피가 타이트하지만 가능한 수준이다. 더 안전한 대안은 점프로 넘기기(지상 돌진이라 수직 회피가 항상 유효)와 대시 무적으로 뚫고 지나가기이며, 코너에 몰렸을 때도 이 두 수단은 남는다
- 결론: 세 변경은 서로 상쇄하지 않는다. 접근은 체감상 완만해지고, 돌진은 예비를 보고 반응 가능하면서도 예전보다 더 큰 위협이 된다

문화 근거

- 개도깨비 계열. 격이 낮고 어수룩하며 꾀에 잘 넘어가는 허당 도깨비 (도깨비 종류 분류의 개도깨비). 쉽게 처치되고 유도당하는 성격을 역할로 번역한다
- 원형의 더벅머리 총각, 패랭이 쓴 장정 형상 (reference 01 3장). 뿔 없음, 사람 형상. 정체가 드러나면 헌 빗자루나 부지깽이로 되돌아가는 처치 연출

판별 신호 (조형 방향)

- 실루엣: 작은 사람 형상. 팔을 치켜든 근접 휘두르기 자세가 대표 실루엣
- 색: 몸은 밤 팔레트의 남보라, 눈은 난색 포인트. 데스매치 시 눈 적색
- 모션: 어수룩하게 다가와 크게 휘두르는 예비동작이 핵심 판별 모션

- 절대 수치 확정 (2026-08-06, D11): 이동속도 60px/s(구 76). 등급은 그대로 M으로 둔다. 플레이어 기준(170px/s) 대비로는 S에 더 가깝지만(0.35배), 이 표의 등급은 개체 간 상대 비교이지 절대 배율 표기가 아니므로 절대치 재조정과 등급 재구간화는 M1 스탯 밸런싱에서 함께 다룬다

상태 머신 특이사항

- APPROACH: 감지 범위(300px) 안에 들면 플레이어를 향해 걸어간다. 속도를 사인파로 흔들어 어수룩한 이동을 만든다. 낭떠러지와 못 넘는 벽에서는 멈춘다(낙사 방지). 공격 쿨다운이 끝나고 거리가 맞으면 WINDUP으로 전이한다
- WINDUP(웅크림 예비, 20f/0.33s): 제자리에 멈춰 다리 부위를 밝게 점멸시키고 예고음을 울린다. 이 구간에 피격당하면 돌진 없이 취소된다(반격 성공). 018 웅크림 클립이 아직 없어 M1 임시 구현은 정지 + 전신 밝기 펄스(부위 분리 스프라이트가 없어 임시로 전신 적용) + 예고음 훅(클립 미배정 시 무음)이며, 실제 클립은 A8 아트 세션에서 교체한다
- 돌진 중(ATTACK)에는 방향이 고정된다(웅크림 종료 시점의 플레이어 위치로 1회 조준, 이후 추적 없음). 근접 헛침(빗맞음) 시 큰 후딜로 반격 윈도우가 열린다. 충돌 STUN은 씨름꾼으로 이관했다
- 근접 패턴도 같은 4단(WINDUP -> ACTIVE -> (반복 시 GAP -> ACTIVE) -> RECOVERY)을 거친다. 예비 구간에는 돌진과 같은 밝기 점멸과 예고음이 붙고, 판정은 접촉이 아니라 전용 AttackHitbox가 담당한다. 접촉 피해(돌진)와 공격 피해(근접 패턴)를 판정 노드 단위로 분리한 것이며 2장의 접촉/공격 피해 구분이 코드에서 성립하는 지점이다
- 판정 반복: 연속 할퀴기는 판정을 2회 켠다. 판정 사이에 빈 구간(3f)을 반드시 두는데, 0이면 Hitbox가 같은 대상을 두 번 때리지 못해 2회 판정이 사실상 1회가 된다 (tests/unit/test_attack_pattern.gd가 이 조건을 고정한다)
- 피격 시 취소: 예비든 판정이든 경직에 들어가면 진행 중인 패턴이 즉시 끝나고 판정이 꺼지며 쿨다운이 걸린다. 처치 시에도 같다. 판정이나 예고가 시체보다 오래 남지 않게 한다

### 5.2 등불 도깨비 (원거리) - M1 우선

정체성과 역할

상태 머신 특이사항

- REPOSITION 사용. 플레이어와 거리를 유지하며 사거리를 확보한다. 접근당하면 짧은 도약으로 이탈(초안 1회, 쿨다운 있음)
- 지형 앵커: 처마와 지붕 위 지정 지점 주변에서만 부유한다. 무한 후퇴로 플레이어를 방 밖으로 끌지 않게 이동 반경을 제한
- 구현 규격 (2026-08-06, D11 2차): 스폰 지점이 앵커다. 배치 슬롯이 곧 앵커이므로 별도 앵커 노드를 두지 않는다. 앵커에서 좌우 56px(anchor_radius)까지만 움직이고, 높이는 앵커 높이로 되돌아오며 진폭 4px 주기 2.2초로 흔들린다. 중력은 받지 않는다(EnemyBase.floating). 방을 비운 사이 떠내려가지 않도록 정지 중에는 수직 속도까지 함께 멈춘다
- 도약 이탈 구현: 44px 안으로 들어오면 진행 중인 투척을 취소하고 앵커 안쪽 방향으로 0.22초간 도약한다(수평 170px/s, 상승 90px/s). 쿨다운 2.6초. 도약 방향은 플레이어 반대쪽을 우선하되 그쪽이 앵커 반경을 벗어나면 반대로 돈다. 앵커 밖으로 도약하면 착지 후 반경 제한과 싸우느라 제자리에서 밀려 보인다
- 도약 이탈에는 예비동작을 두지 않았다. 설계 표의 6f(0.10s)는 반응 임계 14f를 밑돌지만 무피해 회피 기동이라 플레이어가 반응할 대상이 아니다. 반응 임계는 피해를 주는 공격에만 적용한다 (1장 원칙의 범위)

구현과 설계의 정합 (2026-08-06, D11)

- 문제였던 상태: enemy_shooter.gd가 "M1 축약 구현"이라는 자체 주석대로 직선 조준 투사체를 쏘고 중력을 받아 걸어다녔다. 포물선, 착탄 마커, 지형 앵커 부유, 도약 이탈이 전부 빠져 있었다
- 유지 근거 (D11 1차 판단): 이 넷은 등불 도깨비의 정체성 그 자체다. "고지대 화력 + 지형 앵커 부유"가 빠지면 지상을 걷는 재스킨 근접형과 다를 게 없어져 6장 지붕형 방 패턴("고지대 화력에 대한 고도 이동 강제")과 4장의 "원거리는 등불 도깨비" 역할 분리가 무너진다. 확정 5종 중 유일한 원거리이자 유일한 수직 통합 유닛이라 폐기 대신 구현 순서를 정하는 쪽을 택했다
- 처리 결과 (D11 2차): 네 항목을 전부 구현했다. 1차에서 M2로 미뤘던 것을 같은 날 앞당긴 것이며, 우선순위(앵커 > 포물선/마커 > 도약 이탈)는 그대로 유지한 채 순서대로 넣었다. 임시 구현이 남기던 두 한계(마커 없이는 "마커 아래 서기"를 배울 수 없음, 앵커 없이는 방 밖까지 끌려나올 수 있음)도 함께 해소됐다
- 남은 미구현: 처치 시 주변 도깨비불 일괄 점등. 도깨비불 발판 시스템과의 연계라 이 문서 범위를 넘고 M2 과제로 남긴다

M1/M2 확정 항목

- M1 확정 (2026-08-06, D11 2차 / 2026-08-08 사용자 지시로 3항목 개정): 투척 예비(24f), 비행 시간(0.90초)과 투사체 중력(800), 지대 반경(22px), 도약 이탈 쿨다운(2.6초), 앵커 반경(56px). lantern_shooter.tres, patterns/lantern_throw.tres, enemy_shooter.gd/.tscn, lantern_impact.tscn, lantern_bolt.tscn에 반영 완료
- 2026-08-08 개정 3건 (사용자 지시): (1) 착탄 순간 폭발(6f)을 2.0초 지속 불꽃 지대로 바꿨다. 0.40초마다 판정을 다시 켜 머무는 동안 반복 피해를 준다. (2) 날아가는 투사체 자체에 피격 판정을 붙였다(반경 4px에서 6px로). (3) 공격 속도를 1.5배로 올렸다(쿨다운 90f에서 60f). 지대 2.0초는 한 사이클 1.70초(예비 0.40 + 후딜 0.30 + 쿨다운 1.00)보다 길어 0.30초가 겹친다. 이 값을 1.7초보다 크게 올리면 지대가 상시 두 겹이 되므로 올리지 않는다

- M2: 처치 시 도깨비불 일괄 점등 연계 범위, 드랍 테이블

### 5.3 장물아비 (강탈 공격) - M2 (2026-08-09 구현)

정체성과 역할

- 1막 경제 정체성의 전투 번역. 플레이어를 공격하는 적이되, 그 공격에 피격당하면 엽전을 강탈한다. 피격이 체력과 엽전 이중 손실이라 회피 동기가 강하다 (2026-07-25 개정: 비전투 재화 도둑에서 강탈 공격형으로 변경, D2-3에서 위임한 기본 유닛 통일 결정)
- 역할: 일반 근접 압박에 경제 리스크를 얹는다. 다른 적과 섞이면 피격 한 번의 대가가 커져 우선 처치 판단을 만든다
- 2단 행동 유닛이다 (2026-07-27 확정). 강탈 전에는 공격하고, 강탈에 성공한 뒤에는 공격을 멈추고 도망만 친다. 성격이 전투에서 추격전으로 바뀐다. 잡도깨비가 우직하게 오고 우직하게 때리는 무개성 기본형인 것과 대비되는 지점이며, 이동속도도 잡도깨비보다 빠르다

문화 근거

- 도깨비 시장의 장물 경제와 어리숙하면서 심술궂은 도깨비 원형 (reference 01 3장, 02 4번 돈 갚는 도깨비). 훔치고 낚아채는 손버릇을 공격으로 번역

판별 신호 (조형 방향)

- 실루엣: 장물 보따리를 멘 날쌘 형체. 강탈에 성공하면 보따리가 부풀어 보유량을 드러낸다
- 색: 평상시 남보라. 강탈 보유 상태에서 보따리에 난색 하이라이트(회수 표적)
- 모션: 잽싼 접근과 낚아채기 예비동작, 강탈 직후 짧게 물러나는 치고 빠지기

스탯 등급 (초안, M2 확정)

| 스탯 | 등급 |
|---|---|
| 체력 | S |
| 이동속도 | L (잡도깨비보다 명확히 빠르다. 도주 국면에서 최고) |
| 접촉 피해 | S |
| 공격 피해(낚아채기) | M + 엽전 강탈 |
| 감지 범위 | M |

상태 머신 특이사항 (2단 행동)

- 1국면 강탈 전: 표준 접근과 공격을 하는 전투 유닛. 밀착하면 낚아채기 WINDUP으로 넘어간다
- 2국면 강탈 후: 공격을 완전히 멈춘다. 플레이어에게서 멀어지는 방향으로 계속 도망친다. 방 안을 돌며 거리를 유지한다
- 이탈: 도주 상태 진입 후 이탈 타이머가 흐른다. 만료되면 땅을 파는 모션(예비)을 거쳐 사라진다. 땅 파기 모션은 마지막 처치 기회이자 명확한 경고 신호다
- 이탈에 성공하면 강탈분은 회수 불가다. 처치를 강제하지 않고 시간 압박으로 추격 판단을 만든다

공격 패턴 (초안 타이밍, M2 확정)

- 낚아채기 예비를 14f에서 20f로 올렸다 (2026-07-27). 0.23초는 반응 회피 임계를 밑돌아 ENEMIES 1장의 반응 가능성 우선 원칙에 어긋났다. 강탈은 이중 손실이라 특히 확정 피해가 되면 안 된다
- 이탈 타이머와 회수율 감소 곡선은 M2 확정. 초기 가설은 도주 전환 후 10초에 땅 파기 시작이다

감지와 어그로

- 표준. 플레이어를 표적으로 접근한다 (기존 재화 우선 감지에서 변경). 필드 드랍 훔침은 기본 유닛에서 제외하고 소굴 변형에 남긴다

데스매치 변화

- 공격형이므로 공격력 배율의 영향을 받는다. 낚아채기 피해가 상승하되 강탈량 자체는 배율 대상이 아니다 (경제 밸런스 보호). 예비 타이밍과 이탈 타이머는 불변

처치 보상 (시간 압박형 회수)

- 강탈 보유 상태로 처치하면 강탈분을 되찾는다. 회수율은 도주 경과 시간에 따라 떨어진다 (2026-07-27 개정)
- 초기 가설: 도주 전환 후 5초 이내 처치는 전액 + 웃돈, 이후 땅 파기 전까지는 감소하는 비율, 이탈 성공 시 0
- 개정 이유: 상주형에 전액 + 웃돈 반환이면 클리어를 위해 어차피 처치하므로 강탈당하는 편이 이득이 된다. 회피 동기가 강하다는 설계 의도와 반대였다. 이탈 가능성과 회수율 감소가 이 역전을 없앤다
- 강탈 보유가 없으면 표준 전투 드랍(엽전 소)
- 방 클리어 카운트에서는 제외한다. 이탈해 사라진 개체 때문에 방이 영원히 클리어되지 않는 경로를 막는다

배치와 조합

- 방당 최대 1 (이벤트 장물아비 소굴 제외, docs/act1/EVENTS.md 부록 A)
- 씨름꾼과의 동시 배치는 위협 포인트 예산으로 통제한다 (하드 금지 폐지, 6장)
- 잡도깨비와 조합 시 근접 압박 속에서 강탈 회피 우선순위를 시험한다
- 도주 국면이 있으므로 방에 도주 여지(폭 또는 다층)가 필요하다. 극단적으로 좁은 병목 방에는 배치하지 않는다

소굴 변형 관계 (EVENTS 부록 A)

- 이벤트 장물아비 소굴은 이 기본 유닛의 변형이다: 다수 출현, 진입 즉시 소지 엽전 강탈, 방 밖으로 도주해 달리기 추격으로 회수한다
- 기본 유닛은 상주 공격형(피격 시 강탈), 소굴 변형은 진입 강탈과 추격형으로 구분한다. EVENTS 부록 A의 재사용 기반은 이 기본 유닛 위에 소굴 전용 진입 강탈과 추격 UI를 얹는 것이다

M1/M2 확정 항목

- M2: 낚아채기 예비와 강탈량, 치고 빠지기 물러남 거리, 반환 웃돈 배율. 경제 교란 밸런스의 핵심
- M1 제외 (M1 전투 리듬 검증은 잡도깨비와 등불 도깨비. 강탈 메커니즘 체감은 M2 우선)

### 5.4 씨름꾼 (돌진 + 그랩) - M2 (2026-08-09 구현)

정체성과 역할

- 공간 통제와 기동 유닛. 외다리로 도약 돌진해 거리를 좁힌 뒤 강력한 그랩을 건다. 플레이어의 위치 선택과 회피 자원(대시)을 시험한다
- 역할: 돌진으로 회피를 강제하고 그랩으로 잘못된 위치를 처벌한다. 대시 무적 회피의 가치를 확인시키는 구간. 돌진 속성을 잡도깨비에서 이관해 접근과 제압을 한 유닛으로 묶었다 (2026-07-24 조정)

문화 근거

- 외다리도깨비(독각귀) 원형. 다리가 하나여서 껑충 뛰어 움직이고, 밤길에 씨름을 걸며, 왼쪽 다리를 걸어 넘어뜨려야 이긴다는 뚜렷한 공략법이 있다 (도깨비 종류 분류의 외다리도깨비, reference 02 3번)
- 씨름은 풍요 상징이자 도깨비의 대표 놀이. 살상이 아니라 힘겨루기 성격. 격파하면 헌 도구로 되돌아간다

판별 신호 (조형 방향)

- 실루엣: 크고 다부진 외다리 장정. 한 발로 껑충 뛰는 도약과 허리 낮춘 씨름 자세가 판별 신호. 씨름 자세는 모든 공격의 선행 예비이므로 가장 크고 읽기 쉬운 실루엣이어야 한다
- 색: 몸 남보라, 데스매치 시 눈 적색. 그랩 예비 중 손, 약점인 왼다리에 각각 신호 하이라이트
- 모션: 도약 돌진, 긴 그랩 예비동작, 왼다리 방어가 약한 자세

### 방 밀도 (진행도 기준, RUN_STRUCTURE 11.6~11.7)

권위 있는 구조는 RUN_STRUCTURE 11장이다. 2026-08-06 자유 이동 전환으로 층 구조가 폐기됐고, 지도는 노드 34개의 근접 그래프이며 층도 행도 없다. 방 위협 예산은 층 라벨이 아니라 진행도(depth 0~1)가 정한다. 아래 표는 대표값이고 실제 값은 연속이다.

| 진행도 | 위협 예산 | 일반 적 조합 | 의도 |
|---|---|---|---|
| 0.0 (시작 노드) | 3pt | 잡도깨비 단일 | 워밍업. 기본 회피와 반격 학습 |
| 0.3 안팎 | 5pt 안팎 | 2종 조합 | 조합 대응 도입 |
| 0.6 안팎 | 7pt 안팎 | 2종 조합 | 밀도 상승 |
| 1.0 (보스) | 10pt | 최대 3종 조합 | 최고 밀도 |

- 계산식은 `round(lerp(3.0, 10.0, depth) * 2) / 2`다 (scripts/map/run_map.gd threat_budget_for). 0.5 단위 연속값이라 4.5, 6.5, 7.5 같은 예산이 실제로 나온다. 종전의 층별 이산 표(L1 3pt, L2와 L4 6pt, L8 10pt)는 폐기했다
- 생기 고갈 단계마다 +1pt가 더해진다. 3단계면 최대 13pt다 (RUN_STRUCTURE 11.7). 10pt를 넘는 방은 이 경로로만 나온다
- 데스매치 발동 시간 연동의 경계는 8pt다. 8pt 미만 90초, 8pt 이상 110초이며, 그 사이 연속값(6.5, 7.0, 7.5)은 전부 90초 쪽이다 (scenes/levels/room.gd DENSE_BUDGET). 고갈 단계마다 발동이 10초씩 앞당겨진다
- 강제로 지나는 노드가 없다. 중간보스도 신당도 지도 위의 노드일 뿐이라 들르지 않고 지나갈 수 있다 (RUN_STRUCTURE 11.6). "L5 강제 조우 중간보스 고정층"은 폐기된 규칙이다
- 되짚어 들어간 방은 빈 방이다. 적이 다시 차지 않고 통과만 된다 (RUN_STRUCTURE 11.5)
- 이벤트는 전용 노드로 배정된다. 1막 지도의 이벤트 노드는 3개다 (RunMap.KIND_BANDS (2026-08-09 고정 개수에서 범위제로 바뀌었다. 옛 이름 COMPOSITION 은 없다)). 이벤트 상세는 이벤트 설계 문서가 단일 기준이다
- 플랫포밍은 독립 방이 아니라 전투방과 이벤트방 내부 지형으로 흡수된다 (2026-07-24 개정). 일반 적 배치는 전투방 기준을 따른다
- 밀도는 종 수와 웨이브 수로 조절한다. 워밍업 막이라 개체 HP는 낮게 두고 조합으로 난이도를 만든다 (2장)
- 선택방(신당, 상점, 내기방)과 쉼터는 적 배치 없음. 안전 공간의 신뢰를 지킨다 (DESIGN_ACT1 5장)

### 방 클리어 조건 (2026-07-27 신설)

- 기본은 적 전멸이다. 방에 남은 클리어 대상 적이 0이 되면 클리어한다

  - 달걀도깨비: 환경 해저드다. 처치 대상이 아니라 회피 대상이므로 카운트에 넣지 않고, 방 클리어 시 자동 소멸한다. 문서가 6장 요약표와 5.5에서 이미 해저드로 정의했는데 클리어 조건이 전멸이면 결국 전부 잡아야 해서 회피 대응이 페널티만 남았다

- 클리어 카운트 제외 대상은 생기 몰림 타이머의 전투 상태 판정에서도 제외한다. 달걀도깨비만 남은 방에서 타이머가 도는 것은 압박의 오작동이다
- 감투 은신으로 어그로가 풀린 적은 카운트에 남는다. 전투방에는 감투 오브젝트를 배치하지 않아 클리어 우회를 원천 차단한다

### 베이스 클래스 상속

- class_name EnemyBase (CharacterBody2D 상속). 확정 5종과 신규 후보가 공유하는 공통 로직을 담는다: 상태 머신 뼈대, 감지, 피격 반응, 데스매치 오버레이, 사망 처리
- 개체는 EnemyBase를 상속해 공격 패턴과 특이 상태만 구현한다. class_name은 재사용 타입(EnemyBase)에만 부여한다 (CONVENTIONS)
- EnemyBase가 제공하는 공통 훅 (2026-08-06 D11 추가): `floating`(부유형은 중력을 받지 않고 velocity.y를 개체가 관리한다), `can_be_staggered()`(슈퍼아머 구간의 개체가 재정의한다), `set_attack_cooldown(초)`(패턴별 쿨다운을 쓰는 개체가 호출한다), `_on_death_cleanup()`(처치 시 개체별 정리)
- EnemyBase 공통 훅 2026-08-10 추가분. 스프라이트 클립 수와 무관하게 패턴 단계를 눈에 보이게 하고, 개체별 예외를 상속으로 처리한다

| 훅 | 용도 |
|---|---|
| pose_scale, pose_offset, pose_rotation | 매 프레임 목표 자세. _tick_visual 이 보간해 BodyVisual 에 적는다 |

### 상태 머신 방식

- 기본 방식: enum + _physics_process의 match 분기. 프로젝트 초기 단계라 단순함을 우선한다
- 실제 구현은 개체별 지역 enum이다 (2026-08-06 D11). 공통 State enum(3장 표)을 EnemyBase에 두지 않고, 개체가 자기 국면만 담는 enum을 갖는다. 잡도깨비는 근접 패턴 국면(NONE/WINDUP/ACTIVE/GAP/RECOVERY)에 돌진 플래그가 병렬로 붙고, 등불 도깨비는 투척 국면(IDLE/WINDUP/RECOVERY)에 도약 타이머가 병렬로 붙는다. 3장 표는 설계 어휘로 남기고 코드가 1대1로 대응하지는 않는다. 패턴 국면 이름(WINDUP/ACTIVE/RECOVERY)은 플레이어 근접 무기(WeaponMelee.Phase)와 같은 어휘를 쓴다
- 개체별 enum을 택한 근거: 공통 enum에 모든 개체의 국면을 모으면 쓰지 않는 상태가 개체마다 남고, 병렬로 도는 것(돌진 타이머, 도약 타이머)을 단일 상태 변수로 표현하려다 상태 폭발이 난다. 상태와 개체가 늘면 State 노드 패턴(상태별 노드 + 전이)으로 리팩터링을 검토한다. 판단은 미구현 4종 구현 시점
- 정적 타이핑 필수 (project.godot untyped_declaration=2로 엔진 강제). 예: `var state: State = State.IDLE`, `func _enter_state(next: State) -> void:`

### 데이터 분리 (.tres)

- 밸런스 수치는 코드에 하드코딩하지 않고 커스텀 리소스로 분리한다 (CONVENTIONS 데이터 규칙)
- EnemyStats (Resource, class_name): hp, move_speed, contact_damage, attack_damage, detection_range, stagger_level 등. 각 필드 @export로 노출
- AttackPattern (Resource, class_name): windup_frames, active_frames, recovery_frames, cooldown_frames, damage. 개체 스탯이 패턴 배열로 참조
- 개체 스크립트는 `@export var stats: EnemyStats`로 리소스를 주입받는다. 에디터에서 .tres 편집으로 튜닝하며, 이것이 export 튜닝 요구(PROTOTYPE 8장)를 충족한다

### EnemyStats 스키마 확장 (2026-08-06, D11 구현 완료)

D11 1차에서 스키마안을 확정하고 2차에서 코드에 넣었다. 확장 전 필드는 display_name, max_health, move_speed, contact_damage, detect_range, attack_range, attack_cooldown, hitstun, coin_reward, threat_pt 10개였다. threat_pt는 2026-08-05 G8 세션이 이 문서(D11)를 선행해 미리 추가한 것이다(DECISIONS.md 결정 3).

- attack_damage (int, 신설): 공격 판정(히트박스) 피해. 기존 contact_damage는 몸 접촉 피해 전용으로 의미를 좁혔다. 1장의 "접촉 피해와 공격 피해는 구분한다" 원칙이 그전까지 contact_damage 필드 하나로만 성립해 있었다(접촉 피해만 쓰는 M1 2종이라 드러나지 않았을 뿐). 잡도깨비가 접촉 판정(돌진)과 공격 판정(근접 2패턴)을 함께 갖게 되면서 실제로 필요해졌다. 패턴이 있는 공격은 패턴별 damage가 이 값을 덮으므로, attack_damage는 패턴 없는 공격의 기본값 역할이다
- stagger_level (enum, 신설): 3장 피격 반응 규칙의 "경직 약/중/강"을 코드가 읽는 값으로 옮겼다. WEAK/MEDIUM/STRONG 3단계이며 경직 시간 배율(1.0 / 0.7 / 0.45)과 넉백 배율(1.0 / 0.6 / 0.3)로 환산된다. 확정 5종 중 지금 값이 WEAK가 아닌 개체는 씨름꾼(강)과 짐꾼 도깨비(강)뿐이라 M1 2종에는 체감 변화가 없다
- 슈퍼아머는 stagger_level과 합치지 않고 AttackPattern.super_armor(bool)로 분리했다. 경직 강도와 슈퍼아머 여부는 논리적으로 독립이라 하나의 정수로 합치면 씨름꾼처럼 "평소엔 경직 강, 그랩 예비 중에만 슈퍼아머"인 개체를 표현할 수 없다. 외부 경직(유물 개암 한 알 등)도 슈퍼아머를 뚫지 못하게 막았다. 뚫리면 슈퍼아머로 만든 대응 규칙(위치 선택)이 유물 하나로 무의미해진다
- AttackPattern (Resource, class_name, 신설): windup_frames, active_frames, recovery_frames, cooldown_frames, hit_count, hit_interval_frames, damage, range_px, hitbox_size, hitbox_offset, super_armor, 연출 클립 2종. 프레임은 60fps 기준 int로 저작하고 초 환산은 접근자가 한다. 5장 표가 프레임 표기라 .tres를 문서와 1대1로 대조할 수 있고 애니메이션 클립 길이와도 같은 단위다
- hit_count와 hit_interval_frames는 구현 과정에서 추가한 필드다. 5장 표의 "4f 2회"(연속 할퀴기)를 표현할 수단이 스키마안에 없었다. 판정 사이 빈 구간이 0이면 Hitbox가 같은 대상을 두 번 때리지 못해 2회 판정이 1회가 되므로, 반복 판정 패턴은 빈 구간을 반드시 갖는다(테스트로 고정)
- 배치 방식: 공격 프레임은 EnemyStats에 직접 넣지 않고 AttackPattern으로 분리하고, EnemyStats가 `Array[AttackPattern]`으로 참조한다. 개체마다 패턴 수가 달라(등불 1, 잡도깨비 2, 씨름꾼 4 예정) EnemyStats에 패턴별 필드를 늘리면 쓰지 않는 필드가 남고 패턴 추가마다 스키마가 바뀐다. 소유 위치를 개체 스크립트가 아니라 EnemyStats로 정한 것은 무기 쪽 선례를 따른 것이다(WeaponDef가 melee_combo 배열을 갖는 구조)
- 이동 기반 특수행동은 AttackPattern으로 표현하지 않는다. 잡도깨비 예고형 돌진과 씨름꾼 도약 돌진은 windup/active/recovery 3단으로 떨어지지 않고 이동 수치가 본체다. 이쪽은 개체 스크립트의 @export로 둔다
- 이 확장으로 위협 포인트 예산제가 데이터 층에서 완전히 성립한다. threat_pt(예산), attack_damage/contact_damage(피해량), stagger_level(경직 상호작용), 패턴 프레임까지 전부 .tres 권위이고 개체 추가 시 코드 수정이 필요 없다

### 판정 노드 규격 (2026-08-06, D11 신설)

- 접촉 판정과 공격 판정은 노드를 분리한다. ContactHitbox는 몸이 닿는 위협(잡도깨비 돌진, 달걀도깨비 구르기)이고, AttackHitbox는 패턴의 공격 판정이다. 둘을 한 노드로 쓰면 접촉 피해와 공격 피해의 구분이 코드에서 사라진다
- 패턴별로 판정 크기와 위치가 다르므로 AttackHitbox의 CollisionShape2D는 런타임에 패턴 값으로 덮어쓴다. 이때 씬의 shape 서브리소스에 resource_local_to_scene을 켜야 한다. 켜지 않으면 같은 씬의 모든 인스턴스가 하나의 shape를 공유해, 한 마리가 패턴을 시작하면 다른 마리의 진행 중인 판정 크기가 함께 바뀐다 (방에 잡도깨비가 2기 이상일 때 실제로 발생)
- 원거리 착탄 폭발은 적이 아니라 마커 씬(lantern_impact)이 소유한다. 적이 죽어도 이미 날아간 공격은 착탄해야 하므로 투사체와 마커는 방 쪽에 붙인다. 반대로 아직 날아가지 않은 예고는 적이 죽을 때 함께 거둔다

### 충돌 레이어

project.godot [layer_names]에 이미 정의돼 있다(9장 초안 표를 코드 기준으로 정정, 2026-08-06 D11. 기존 초안은 10비트/다른 이름이었고 실제 구현과 어긋나 있었다).

| 비트 | 이름 | 용도 |
|---|---|---|
| 1 | world | 지형, 벽 |
| 2 | player_body | 플레이어 본체 |
| 3 | enemy_body | 적 본체 |
| 4 | player_hurtbox | 플레이어 피격 판정 |
| 5 | enemy_hurtbox | 적 피격 판정 |
| 6 | player_hitbox | 플레이어 공격 판정 |
| 7 | enemy_hitbox | 적 공격 판정 |
| 8 | projectile | 투사체 |
| 9 | oneway | 원웨이 발판 |

- Hurtbox는 상대 hitbox 레이어를 감시(mask)하고, Hitbox는 상대 hurtbox 레이어에 노출(layer)한다. 아군 오사 방지를 위해 적 hitbox는 player_hurtbox만 겨냥한다
- pickup과 detection 전용 비트는 실제로는 두지 않았다. 드랍 픽업은 Area2D 그룹(is_in_group)으로, 감지 영역은 EnemyBase.distance_to_player()의 스칼라 거리 비교로 대체 구현됐다(3장 감지 규칙 참고, DetectionArea 노드 자체는 M2 스키마 확장과 함께 재검토)

### 통신 (call down, signal up)

- 부모(방, 스포너)는 자식(적)을 직접 호출한다. 적은 시그널로 상위에 알린다 (CONVENTIONS)
- 시그널 (과거형 snake_case): died, health_changed, attack_started, staggered, enraged_changed
- 데스매치 발동: 전투방이 방 안 적에게 오버레이를 call down 하거나 이벤트 버스로 방송한다. 적은 enraged_changed로 연출을 갱신
- 드랍: died 시그널을 방 또는 드랍 매니저가 받아 처리한다. 적 스크립트는 드랍 생성 책임을 지지 않는다 (결합 최소화)

## 1. 이벤트 노드 모델 (RUN_STRUCTURE 10장 정합)

- 정의: 이벤트는 노드 맵의 전용 노드 종류다. 1막 배정표에서 L2와 L8은 전투의 대안으로, L7은 신당의 대안으로 배치된다 (RUN_STRUCTURE 3장, 2026-07-27 9층 개정). 플랫포밍 노드 자리를 이벤트 노드가 대체하며, 플랫포밍 지형은 이벤트방 내부 지형으로 흡수한다
- 진입 시 확정: 이벤트 노드에 진입하면 하나의 P(긍정) 또는 N(부정) 결과가 발생한다. 어떤 결과가 나올지는 맵 생성 시 시드로 이미 확정돼 있다 (재현성과 경로 예산 검사를 위해 생성 시 고정, RUN_STRUCTURE 7장 콘텐츠 선택 단계)
- 확률 표시: 노드 맵에는 그 노드의 P/N 발생 확률을 표시한다 (예: 좋음 60 / 나쁨 40). 확률은 플레이어의 리스크 정보이며, 구체 콘텐츠는 진입 전까지 비공개다
- 점수(RUN_STRUCTURE 10장)
  - 이벤트 노드의 종류 기본 점수는 0(중립)이다. 막 기준치 B 계산에는 0으로 들어간다
  - 실제 점수는 확정된 P/N 결과의 값이며, 절대값 10~30 범위다 (2026-07-27 축소. 옛 범위 10~40). 경로 예산 검사는 이 실점수로 수행한다 (실점수 검사, 10장 규칙 12)
  - 큰 값(절대값 30) 결과는 변동성 통제를 위해 막당 소수로 제한한다 (10장 변동성 원칙)
- 공개 수준: 노드 종류(이벤트)와 P/N 확률은 맵 전체 공개. 구체 결과 콘텐츠는 비공개 (정보 공개 원칙과 도박의 긴장을 동시에 지킨다)

## 2. 확률 등급 (odds tier)

이벤트 노드는 세 확률 등급 중 하나로 생성된다. 등급은 플레이어에게 리스크 수준을 읽어주고, 생성기에는 경로 예산을 조정하는 손잡이가 된다. 결과 자체는 생성 시 시드로 확정되며, 등급은 그 확정에 쓰인 가중치이자 표시 정보다.

| 등급 | 표시 (초안) | 좋음 확률 | 용도 |
|---|---|---|---|
| 좋은 예감 | 좋음 70 / 나쁨 30 | 높음 | 긍정 기대. 낮은 리스크 선택지 |
| 반반 | 좋음 50 / 나쁨 50 | 중간 | 표준 도박 |
| 스산함 | 좋음 30 / 나쁨 70 | 낮음 | 고위험. 큰 값 결과와 자주 짝지음 |

- 구현 (2026-08-06): 등급 3종은 resources/events/odds/의 .tres 3개이며 확률과 등급별 추첨 가중치를 데이터로 둔다. 클래스는 scripts/data/event_node_config.gd다. 노드 맵이 표시하는 확률은 이 .tres의 positive_chance에서 바로 나오므로 표시와 확정이 어긋날 수 없다 (테스트 E8)
- 표시 수치는 초안이다. M2 시드 시뮬레이션에서 조정한다
- 등급과 실제 결과의 관계: 결과는 생성 시 고정이라 "좋은 예감"이라도 드물게 부정 결과가 확정될 수 있다. 확률은 정직한 리스크 정보이지 보증이 아니다. 플레이어에게는 도박으로 체감된다
- 색 신호는 10장 UI 규칙을 따른다 (10.1)

## 3. 이벤트 결과의 3요소와 발동 방식

각 P/N 결과는 세 요소로 정의한다. 데이터 스키마(8장)와 구현이 이 구조를 따른다.

- 트리거: 이벤트방 진입 후 결과가 전개를 시작하는 조건
- 전개: 방 안에서 벌어지는 변화 (지형, 적, 오브젝트, 상태 효과)
- 결과: 해소 시 얻거나 잃는 것. 순점수의 근거

발동 방식 4종 (이벤트방 안에서 결과가 어떻게 전개되는지)

| 방식 | 정의 | 대표 결과 |
|---|---|---|
| 자동 (AUTO) | 진입 즉시 방 상태를 바꾼다 | 야시장 대목, 어둑 골목, 돌림 도깨비 |
| 선택 (OPT_IN) | 상호작용해야 보상 또는 위험이 발생 | 방망이 한 방, 도깨비 터, 취객 상인 |
| 조건부 (CONDITIONAL) | 플레이어 행동이 위험을 유발 | 성난 상인회, 통행세, 도깨비 씨름 도전 |
| 해금 (UNLOCK) | 전투 클리어가 서사 해금 조건 | 대장장이 구출 |

구현 (2026-08-06): 발동 방식 4종은 EventOutcome.Trigger로 데이터에 있다. 실제 전개까지 붙은 것은 자동(AUTO) 3종뿐이다. 씨름 대결과 장물아비 추격은 미니게임 오버레이로, 도깨비불 축제는 즉시 효과로 처리한다. 선택, 조건부, 해금의 방 안 상호작용은 이벤트방 슬롯 전환 뒤 후속 세션에서 붙인다.

방 성격 (이벤트방 템플릿 요구)

- 각 결과는 방 성격 태그를 가진다: 전투형(combat), 플랫포밍형(platforming), 상호작용형(interaction)
- 이벤트방 템플릿(RUN_STRUCTURE 6장, 2개)은 세 성격을 모두 수용해야 한다. 전투형은 적 슬롯과 웨이브 게이트, 플랫포밍형은 발판과 갭, 상호작용형은 오브젝트와 프롬프트를 배치한다
- 플랫포밍 지형이 이벤트방으로 흡수되므로, 플랫포밍형 결과가 최소 2종 이상 유지되게 한다 (도깨비불 축제, 도깨비보 지름길)

## 4. 긍정 P 콘텐츠 (8종)

형식: 이름 (점수, 발동, 방 성격) / 선행 조건 / 설화 근거 / 전개 / 결과 / 상호작용 / 확정 시점 / M2

### P1. 대장장이 구출 (+30, 해금, 전투형)

- 선행: 대장장이 미해금(blacksmith_locked), run_once. 큰 값(30)이라 막당 소수 제한 대상
- 설화: GDD 5장 NPC 해금, GDD 8장 대장장이 도깨비
- 전개: 방 한켠 우리에 갇힌 대장장이 도깨비. 전투 클리어 시 해방
- 결과: 무기 강화 1회 즉시 제공 후 대장장이가 허브에 영구 합류 (무기 해금과 강화 담당)
- 상호작용: 메타 프로그레션. 성사 시 blacksmith_locked 해제, 이후 런 풀에서 제거
- 확정: 강화 수치 밸런싱. 미해금 런에서 등장 가중(초안)
- M2 우선 (핵심 해금 경로)

### P2. 방망이 한 방 (+30, 선택, 상호작용형)

- 선행: 없음. 큰 값(30)이라 막당 소수 제한 대상
- 설화: 도깨비방망이(설화 1). 두드리면 재물이 나오는 요술방망이
- 전개: 도깨비가 버리고 간 방망이 습득. 두드리면 보상이 쏟아진다
- 결과: 3택 보상(엽전 대 / 소모품 묶음 / 무기 강화 1회) 중 1회 선택. 방망이는 살상 무기가 아니라 생산 도구로 연출 (설화 원형 준수)
- 상호작용: 무기 도깨비 방망이(GDD 7장)와 별개. 조형과 연출로 혼동 방지
- 확정: 보상 등급 밸런싱
- M3

### P3. 야시장 대목 (+20, 자동, 전투형)

- 선행: 없음. 좌판 거리 테마 우선
- 설화: 도깨비 잔치판(설화 1), 시장 거래(민속 5)
- 전개: 좌판 밀도 2배, 파괴 드랍 상향
- 결과: 파괴 드랍 대폭 상향. 좌판 파괴 어그로 규칙 유지 (파괴 선택의 긴장 유지). 놋대야 등 규칙 개조 유물 보유 시 유물 규칙이 우선한다 (RELICS 6.2 9번, 2026-08-05 D6)
- 상호작용: 좌판(DESIGN_ACT1 2.6). N4 성난 상인회와 공존하되 P/N 표식과 방 내 판별 신호로 구분(부록 B.0). 놋대야 유물(RELICS 9) 시너지
- 확정: 드랍 배율 밸런싱
- M2 우선 (좌판 재사용)
- 구현 직전 상세: 부록 B

### P4. 돈 갚는 도깨비 (+20, 자동, 전투형)

- 선행: 없음
- 설화: 돈 갚는 도깨비(설화 4). 어리숙한 도깨비가 갚을 필요 없는 빚을 반복 지급
- 전개: 어리숙한 도깨비가 방 안을 돌며 주기적으로 엽전을 흘린다(줍기). 방 퇴장 시 종료
- 결과: 체류 시간당 엽전 획득
- 상호작용: 생기 몰림 데스매치(RUN_STRUCTURE 9장)와 트레이드오프. 오래 머물수록 엽전은 늘지만 광폭화 위험 증가. 얼마나 챙기고 나갈지가 선택
- 확정: 지급 주기와 양 밸런싱
- M3

### P5. 취객 상인 (+10, 선택, 상호작용형)

- 선행: 없음
- 설화: 영감이 소주를 좋아함(민속 2), 김서방 도깨비(설화 10)
- 전개: 취한 도깨비 상인이 소모품 1개를 반값에 판다
- 결과: 소모품 반값 구매 기회(엽전 필요)
- 상호작용: 상점 경제
- 확정: 상품 풀과 할인율 밸런싱
- M3

### P6. 메밀묵 고사상 (+10, 선택, 상호작용형)

- 선행: 없음
- 설화: 고사 음식 메밀묵, 막걸리, 팥시루떡(민속 4). 메밀은 도깨비 최애 음식
- 전개: 고사상 발견. 취식 시 일시 식사 버프
- 결과: 다음 몇 개 방 동안 유지되는 버프(회복 또는 공격/방어 소폭). 허브 주모 식사 버프 시스템 재사용
- 상호작용: 허브 주모(GDD 8장) 버프
- 확정: 버프 종류와 지속 밸런싱
- M3

### P7. 도깨비불 축제 (+10, 자동, 플랫포밍형)

- 선행: 없음
- 설화: 도깨비불(설화 6). 밤 들판에 줄지어 나타나는 불
- 전개: 방 전체 도깨비불 상시 점등
- 결과: 플랫포밍 난이도 하락(발판 안정) + 소량 엽전
- 상호작용: 도깨비불 발판(DESIGN_ACT1 3장)
- 확정: 도깨비불 지속시간 규칙과 정합(M1)
- M2 우선 (도깨비불 재사용, 플랫포밍형 확보)

### P8. 도깨비보 지름길 (+10, 자동 개통 + 선택 진입, 플랫포밍형)

- 선행: 없음. 지붕 위, 골목 테마 우선
- 설화: 도깨비 다리와 둑(설화 7). 하룻밤에 다리와 보를 쌓는 신통력
- 전개: 도깨비들이 하룻밤에 놓은 다리와 발판이 나타난다
- 결과: 숨은 탐색 보상 접근로 또는 빠른 출구 지름길 개통
- 상호작용: 비밀방 진입구, 절차 생성 당위(설화 7)
- 확정: 보상 배치와 지름길 규격(M1 이동 규격 후)
- M3 (플랫포밍형 확보 후보)

## 5. 부정 N 콘텐츠 (8종)

축소 근거와 예산 여유 (2026-07-27 산술 검증)

1막 기준치 B는 +25, 허용 범위는 -50에서 +100이다 (RUN_STRUCTURE 10장, 결정 25 W = 자유 층 수 x 15 = 75 반영). 고정층 4개(L1 -20, L3 +40, L5 -40, L9 +40)의 합이 +20이므로 자유 층 5개(L2, L4, L6, L7, L8)의 합이 -70에서 +80 안에 들어야 한다.

| 자유 층 | 배정 후보 | 점수 폭 (신 범위) |
|---|---|---|
| L2 | 전투 또는 이벤트 | -30 ~ +30 |
| L4 | 전투 또는 내기방 | -20 ~ 0 |
| L6 | 상점 또는 내기방 | 0 ~ +30 |
| L7 | 신당 또는 이벤트 | -30 ~ +40 |
| L8 | 전투 또는 이벤트 | -30 ~ +30 |

- 이론 최대는 +130, 최소는 -110이며 자유 층 합 허용 창(-70에서 +80)을 양쪽으로 벗어난다. 자유 층이 4개에서 5개로 늘고, 신설한 L7이 신당(+40)과 이벤트(-30) 사이에서 70점을 스윙하기 때문이다. 생성기는 이 이론 극값 경로를 DP 예산 검사와 부분 재배정으로 회피한다 (RUN_STRUCTURE 10장)
- 유효 배치는 존재한다. 예를 들어 L2 전투(-20), L4 전투(-20), L6 상점(+30), L7 신당(+40), L8 전투(-20)면 합 +10으로 통과한다. 다만 생성기가 극값 경로를 피해 가는 부담이 커졌다
- 해소 (2026-07-29): 위 항목은 결정 25(허용 폭 W = 자유 층 수 x 15)로 해소됐다. 1막 자유 층 5개 기준 허용 폭 75. 상세는 RUN_STRUCTURE 10장과 docs/DECISIONS.md 참고
- M2 시드 시뮬레이션에서 폴백 발생률(초안 상한 5퍼센트)을 우선 감시 대상으로 둔다. 초과 시 다음 순서로 조정한다. 첫째 허용 폭을 자유 층 수 연동으로 전환, 둘째 경로당 이벤트 노드 최대 1개 제약 추가, 셋째 이벤트 범위를 10~20으로 재축소
- 점수는 기준치 계산에서 제외되고 실점수 경로 검사에만 반영된다 (10장). P/N 균형(합 0)은 요구하지 않는다. 편차는 확률 등급 배정과 경로 예산 검사가 통제한다
- 풀 평형 규칙 제외 (2026-07-27 명문화): RUN_STRUCTURE 10장 테스트 규칙 11(풀별 개별 가감의 합 0, 허용 오차 ±5)은 이벤트 P/N 풀에 적용하지 않는다. 그 규칙은 중간보스 개체처럼 종류 기본 점수 위에 얹는 가감을 대상으로 하며, 이벤트 P/N은 가감이 아니라 결과 자체의 점수다. 현행 풀 합계는 P +140, N -130으로 순 +10이며 이는 위반이 아니다
- 내기방 3유형은 별도 노드 종류(중립 0)이며 이 표의 대상이 아니다(7장)

## 7. 내기방 (별도 노드 종류, 3유형)

- 성격: 내기방은 이벤트 노드가 아니라 별도의 선택방 계열 노드 종류다. RUN_STRUCTURE 3장 1막 배정표에서 L4, L6에 노출 후보로 배치된다(선택 보장 아님). 종류 기본 점수 0, 중립. 기대값 중립으로 설계한다
- 공통: 모두 플레이어가 선택 진입한다. 안전방 성격이나 씨름판과 제한시간 유형은 자발적 전투를 유발한다. 방마다 시드로 1유형이 열린다
- 설화 근거: 도깨비와 내기, 수수께끼(설화 9). 도깨비는 씨름 외에 내기와 시합을 즐긴다

### B1. 노름판 (투전, 골패, 썅륙)

2026-08-06 재설계. 옛 스펙(야바위, 홀짝)은 폐기했다. 조선 노름 3종으로 바꿔 1막 정체성(경제와 선택)에 붙이고, 방마다 다른 게임이 열려 반복감을 줄인다.

- 진행: 방에 들어서면 노름꾼이 자리를 내주며 말을 건다. 한 판 붙을 수도 있고 그냥 지나갈 수도 있다. 방마다 시드로 게임 1종이 열린다
- 판수: 최대 3판. 걸 돈이 최소 베팅에 못 미치면 그 자리에서 끝난다. 판 도중에도 자리를 뜰 수 있다
- 베팅: 소지 엽전에서 건다. 한 판 최대 베팅은 소지금의 절반이다(초안). 이기면 배당을 받고 지면 건 돈을 잃는다

게임 1. 투전

- 플레이어와 노름꾼이 각각 투전 패 2장을 받는다
- 두 패의 숫자를 더한 끝자리가 9에 가까운 쪽이 이긴다
- 두 장의 숫자가 같으면 땡이 되어 어떤 끗보다도 높다 (1땡이 9끗을 이긴다). 땡끼리는 숫자가 큰 쪽이 이긴다
- 서열이 같으면 무승부이고 건 돈을 돌려받는다

게임 2. 골패

- 각각 골패 2장을 받는다. 골패 한 장에는 두 쪽에 점이 찍혀 있다
- 패에 찍힌 점을 모두 더한 끝자리가 높은 쪽이 이긴다
- 같으면 무승부이고 건 돈을 돌려받는다

게임 3. 썅륙

- 주사위 2개를 던지기 전에 어디에 걸지 고른다
- 소: 두 눈의 합이 2에서 6. 배율 2배(초안)
- 대: 두 눈의 합이 8에서 12. 배율 2배(초안)
- 쌍: 두 눈이 같음. 배율 5배(초안)
- 합이 7이면 하우스가 가져간다. 이 규칙이 세 베팅의 기대값을 같게 만든다

기대값과 미결정

- 투전과 골패는 무승부 환급이라 기대값 1.0(중립)이다. 썅륙은 합 7 하우스 승 때문에 초안 배당에서 세 베팅 모두 0.833이다
- 내기방 종류 기본 점수가 중립 0인 근거는 기대값 중립(10장)이므로 썅륙의 기대값 미달은 규칙 위반이다. 쌍 배율을 6배로 올리면 쌍만 1.0이 되고 소와 대는 여전히 0.833이라 배율만으로는 해소되지 않는다. 밸런싱에서 셋 중 하나로 정한다. 첫째 소와 대의 배율을 2.4배로 올린다, 둘째 합 7 하우스 승을 폐기한다, 셋째 내기방 종류 기본 점수를 음수로 재산정한다 (docs/DECISIONS.md 2026-08-06)
- 설화 반영: 도깨비가 잘 속는 성질을 관찰 승률로 옮길지는 밸런싱에서 결정한다

## 9. 생성과 확정 알고리즘 (RUN_STRUCTURE 7장, 10장 연계)

### 9.1 이벤트 노드 확정 절차

RUN_STRUCTURE 7장 생성 절차의 콘텐츠 선택 단계(종류 배정 후, 검증 전)에서 수행한다.

구현 완료 (2026-08-06): scripts/systems/event_resolver.gd. RunMap.generate가 구조를 만든 뒤 EventResolver.resolve가 이벤트 노드에 결과를 확정한다. 확정값은 RunMapNode의 odds_tier, positive_chance, outcome_id, outcome_score, outcome_polarity, outcome_flavor, outcome_trigger, theme에 들어간다. 노드마다 (지도 시드, 노드 id)로 파생한 서브 시드를 쓰고 노드를 id 오름차순으로 처리해, 중복 금지와 big_value 한도까지 결정적이다.

방 테마: 배정표에 방 테마 개념이 없어 생성기가 노드마다 street, roof, alley 중 하나를 시드로 배정하고 theme_tags 필터에 쓴다. 태그가 맞는 후보에 가중치 3, 태그가 없는 후보에 1을 준다.

폴백 사다리: 노드를 결과 없이 두지 않는 것이 우선이라 아래 순서로 규칙을 하나씩 놓는다. 첫째 확정된 극성에서 고른다. 둘째 반대 극성에서 고른다(그 극성 후보가 필터로 전부 빠진 경우). 셋째 중복 금지를 놓고 다시 고른다. 셋째 단계가 필요한 이유는 이벤트 노드 수가 추첨 풀보다 클 수 있기 때문이다. 1막 지도의 이벤트 노드는 3개다 (2026-08-09 정정: 종전 표기 "자유 층 3개가 전부 최대 폭이면 12개"는 폐기된 층 구조에 기댄 값이다. 현재 기준은 RunMap.KIND_BANDS (2026-08-09 고정 개수에서 범위제로 바뀌었다. 옛 이름 COMPOSITION 은 없다)이다). implemented 결과가 그보다 적으면 중복 없이 채울 수 없다. 콘텐츠가 늘면 이 단계는 자연히 안 쓰인다. 테스트 E7은 노드 수가 풀 크기 이하인 맵만 검사한다.

- 입력: 종류 배정된 노드 맵, 막 서브 시드, 런과 메타 상태(해금 플래그), 1막 P 풀과 N 풀
- 절차 (이벤트 종류로 배정된 각 노드에 대해)
  1. 확률 등급 배정: 시드로 OddsTier 선택 (초안 분포는 M2 튜닝)
  2. 극성 확정: 등급의 positive_chance로 시드 롤 → P 또는 N 확정
  3. 결과 선택: 해당 극성 풀에서 시드 가중 선택. 필터(방 성격 수용, 테마 태그 부합, 선행 조건 충족, run_once 미사용, 이번 런 중복 제외, big_value 막당 한도 준수)
  4. 노드 실점수 = 결과 score. 노드 표시 확률 = 등급 표시값
- 출력: 결과가 확정된 이벤트 노드 맵. 경로 점수 검사는 실점수로 수행(RUN_STRUCTURE 10장 규칙 12)

### 9.2 예산 위반 시 재조정 (RUN_STRUCTURE 10장 재배정 전략 연계, 제안)

미구현 (2026-08-06 판단). RUN_STRUCTURE 10장의 DP 예산 검사와 부분 재배정 자체가 아직 없어 선행이 없다. 이 세션에서는 실점수를 노출하는 인터페이스(RunMap.node_actual_score, RunMap.path_score)까지만 만들었다. 예산 검증기를 구현하는 세션에서 아래 제안의 채택 여부를 함께 정한다.

- 이벤트 노드는 자유 층(L2, L7, L8)의 변동 노드다. RUN_STRUCTURE 10장 부분 재배정의 대상이다
- 제안(M2 확정): 예산 위반 시 노드 종류를 바꾸기 전에 이벤트 노드의 결과를 먼저 재조정한다(다른 극성 또는 다른 점수의 결과로 재확정, 또는 확률 등급 변경). 이벤트 결과 교체는 노드 종류 교체보다 되돌리기 비용이 낮다. 시드 결정적으로 수행
- 보장 규칙(고정층, 선택 보장, 연속 금지)은 그대로 우선한다. 이벤트 노드는 자유 층에만 있어 보장과 충돌하지 않는다

### 9.3 선행 조건과 런 상태

- prerequisites는 런 시작 시점의 메타 또는 런 플래그를 참조한다(예: blacksmith_locked). 충족되지 않으면 P 풀 후보에서 제외
- run_once 결과는 런 내 1회, 성사 시 플래그 갱신(대장장이 해금 시 blacksmith_locked 해제 → 이후 런 풀에서 제거)
- big_value(절대값 30) 결과는 막당 한도(초안 1개)를 두어 변동성을 통제한다

## 부록 A. 장물아비 소굴 (N2) 구현 직전 스펙

2026-08-06 개정. 측면 플랫포머 추격에서 탑뷰 5레인 달리기로 바꿨다 (사용자 결정). 부정 유지(순점수 -20), 성공 보상에 떨이 유물 추가는 그대로다.

탑뷰로 바꾼 이유: 측면 추격은 방 안 이동 문법과 같아서 별개의 손맛이 나오지 않았다. 탑뷰 레인 달리기는 카메라와 조작이 본편과 달라 조우 자체가 사건으로 읽히고, 좌우 회피와 따라붙기라는 단순한 축 하나로 긴장을 만든다. 대신 방 안 지형 재사용(짐수레, 항아리, 창고 판벽)은 포기했고, 장물아비 개체를 방에 배치하지 않으므로 ENEMIES 5.3의 방당 1 제한 해제 예외도 필요 없어졌다.

### A.0 성격과 결정 (재확인)

- 극성과 점수: N, 순점수 -20 유지. 자동 발동. room_flavor = PLATFORMING (탑뷰 달리기는 방 성격 태그와 무관한 별도 미니게임이라 태그는 표기로만 남긴다)
- 부정 유지 근거: 진입 즉시 소지 엽전을 뺏기고, 성공해도 되찾는 데 그친다(알파와 떨이 유물은 소소). 놓치면 손실이라 순가치는 음수다. 유물을 떨이(하급)로 한정해 긍정 전환급 오버밸런싱을 막는다 (사용자 결정 2026-07-25)
- 재편 취지: 필드 재화를 지키는 정적 전투에서, 뺏긴 것을 쫓아 되찾는 달리기로. RUN_STRUCTURE 중간보스 이벤트형(달리기)과 결이 같은 일반 이벤트 티어 버전
- 설화: 장물 경제와 어리숙한 도깨비(reference 01 3장, 02 4번). 훔친 뒤 흘리며 달아나는 원형이 추격 유도와 맞는다

### A.1 발생 조건 (진입 시 판정)

- 노드 배치: 다른 N 이벤트 결과와 동일하게 자유 이벤트 노드에 배치된다. 특별한 위치 제약은 없다
- 진입 판정: 방 진입 시 플레이어 소지 엽전을 확인한다
  - 문턱 이상(min_coins_trigger): 장물아비가 강탈하고 추격이 시작된다(A.3). 소굴 본편
  - 문턱 미만: 훔칠 게 없어 장물아비가 "이런 거지를 털어 무엇하나" 식으로 비웃고 물러나며, 방은 일반 전투로 전환된다. 표준 1막 전투 아키타입(잡도깨비 등, ENEMIES) 웨이브가 채워지고 장물아비는 전투에 참여하지 않는다(공격 없음). 클리어 시 일반 전투 보상만, 유물 없음
- 전환 근거: 불발로 경험값을 0으로 만들면 N 등급이 무색해진다(사용자 지적). 일반 전투로 전환해 노드가 부정 경험을 유지하게 한다. 실효 점수는 전투 노드 수준(약 -20)으로 소굴 본편(-20)과 사실상 같으나, 강탈과 추격 부담이 없어 체감만 가볍다
- 뺏기는 양은 소지금에 비례(하한 있음). 유물 보상은 소지금과 무관하게 전원 처치 시 고정(소굴 본편 한정)
- 설계 의도: 부자만 노린다는 서사. 발생 조건은 노드의 존재 여부가 아니라 진입 시점에 소굴 본편이 발동하느냐 일반 전투로 전환되느냐다

### A.2 달리기 구성 (탑뷰 5레인)

- 화면: 전용 오버레이다. 방 위에 전체 화면으로 뜨고 도는 동안 방과 생기 몰림 타이머는 멈춘다
- 레인: 5개. 플레이어는 화면 아래에 고정되고 좌우로 레인만 옮긴다. 조작은 좌우 이동뿐이다
- 장애물: 위에서 아래로 흘러 내려온다. 한 줄에 1에서 3개까지 놓이며 지나갈 레인을 최소 2개 남긴다(막다른 길 금지)
- 표적: 한 번에 한 마리씩 쫓는다. 표적은 주기적으로 한 칸씩 레인을 옮기며 도망친다. 보따리에 난색 하이라이트를 찍어 우선 포착 신호로 삼는다(A.6)
- 따라붙기: 거리가 시간에 따라 줄어든다. 거리가 0이 됐을 때 레인이 같으면 잡고, 어긋나면 거리가 다시 벌어진다
- 충돌: 장애물에 부딪히면 거리가 벌어지고 충돌이 쌓인다. 세 번 부딪히면 남은 장물아비를 놓친 채 끝난다

### A.3 상태 흐름

1. 진입 판정: 소지 엽전이 min_coins_trigger 미만이면 장물아비가 비웃고 물러난다. 방은 일반 전투로 이어진다(A.1, 2026-07-25 결정 유지. 0 경험값을 만들지 않는다)
2. 강탈: 문턱 이상이면 장물아비들이 소지 엽전의 일부를 낚아채 달아난다. 뺏긴 액수를 개체 수로 나눠 각자 나눠 갖는다
3. 달리기: 탑뷰 화면으로 전환된다. 좌우로 장애물을 피하며 표적에 따라붙는다
4. 포착: 거리가 0일 때 레인이 같으면 잡는다. 그 개체가 가진 것을 회수 대상에 넣고 다음 표적으로 넘어간다
5. 종료: 전원을 잡거나 세 번 부딪히면 끝난다. 놓친 개체가 가진 것은 손실이다
6. 정산: 회수액에 웃돈을 얹어 돌려주고, 전원 처치면 떨이 유물 1개를 준다. 결과 팝업이 회수와 손실을 나눠 보여준다

### A.4 보상

- 전원 처치: 뺏긴 돈 전액 회수 + 알파(회수액의 소량 웃돈) + 떨이 등급 유물 1개
- 유물: docs/systems/RELICS.md 1막 풀의 떨이 등급에서 추첨한다(예: 도깨비 방망이 기념품, 부지깽이 토막, 멍석 조각, 개암 한 알, 라이터). 구체 풀과 확률은 D2-4 유물 세션이 확정한다. 서사는 장물아비들이 쟁여둔 장물(떨이)을 되찾는 것
- 부분 클리어: 처치한 개체분만 회수. 유물 없음
- 실패(전원 놓침): 뺏긴 돈 손실. 유물 없음

### A.5 점수 산정 (RUN_STRUCTURE 10장 실점수)

- 순점수 -20 유지: 위험 -40(뺏긴 돈 손실과 추격 부담) + 보상 +20(전원 처치 시 회수, 알파, 떨이 유물). 유물이 떨이(소 규모)라 보상 성분이 크게 오르지 않아 음수를 유지한다 (2026-07-27 점수 축소로 -30에서 하향, 2026-08-05 D6 정합)
- 큰 값 아님(-20). 생성 시 고정하고 DP 경로 예산 검사에 반영한다(E9)
- 검증: 떨이 유물 추가로 실효 순가치가 -20보다 높아지는지 M2 시드 시뮬레이션에서 확인한다. 상향되면 유물 확률을 낮추거나 점수를 재조정한다
- 저소지 진입(일반 전투 전환): 강탈과 추격 대신 표준 전투가 되어 실효 점수는 전투 노드 수준(약 -20)이다. 0으로 떨어지지 않아 N 등급이 유지된다(사용자 지적 반영). 생성 시 -20 고정이며 저소지 전환 시에도 전투 노드 수준(약 -20)이라 편차가 거의 없다. M2 시드 시뮬레이션에서 감시한다

### A.6 UI와 UX (색 채널 준수)

- 노드: N 극성 표식(남색과 회색). 적색과 청록 금지. 내용 비공개
- 진입: 짧은 강탈과 산개 연출. 대사 최소(Dead Cells 상한)
- 개체별 이탈 게이지 바와 화면 밖 추적 화살표. 보따리 난색 하이라이트가 우선 포착 신호다
- 결과: 회수, 알파, 유물 획득 팝업과 놓친 손실 표시

연출 (2026-08-07)

도형(원과 사각)만 그리던 초판에 조형과 상호작용 반응을 넣었다.

- 골목: 화면 가운데 세로로 바닥을 깔고 좌우에 좌판을 늘어놓는다. 레인 경계의 점선과 좌판이 아래로 흘러 달리는 속도를 알린다. 화면 위로 갈수록 조형이 작아져(배율 0.52에서 1.0) 멀리 보인다
- 사람: 플레이어는 달리기 클립, 장물아비는 도깨비 뜀 클립을 쓴다. 장물아비 등의 보따리는 등불 호박 점으로 찍어 A.6의 우선 포착 신호를 지킨다
- 장애물: 궤짝과 돌 조형을 자리 번호로 골라 배치한다(같은 자리에는 늘 같은 조형). 지나간 장애물은 흐리게 바꾼다
- 반응: 부딪히면 화면이 남색으로 물들고 흙먼지가 튀며 플레이어가 잠깐 뒤로 밀린다. 잡으면 엽전이 튀고 "잡았다"가 떠올랐다 사라진다. 레인을 옮길 때 몸이 따라오며 기울어진다
- 남은 충돌 여유는 등불 세 개로 보인다. 꺼진 등이 부딪힌 횟수다
- 배치 확인은 tools/pipeline/previz_chase.py로 한다

### A.7 엣지 케이스

- 소지금 문턱 미만(엽전 0 포함): 소굴 본편 대신 일반 전투로 전환. 장물아비가 비웃고 물러난 뒤 표준 전투 웨이브가 진행되며 유물은 지급하지 않는다(A.1)
- 부분 처치: 정상. 유물은 전원 처치 조건이다
- 데스매치 발동: 소굴의 장물아비는 진입 강탈 후 도주와 추격이 중심인 소굴 변형이라 직접 공격 비중이 낮다 (기본 장물아비는 공격형, ENEMIES 5.3과 구분). 이탈 게이지는 데스매치와 독립이며, 혼합 잡도깨비만 공격력 배율의 영향을 받는다
- 감투 은신(DESIGN_ACT1 3장): 감투는 접촉 강탈만 회피한다. 이미 뺏긴 뒤 추격 국면에는 영향이 없다
- 전원 이탈 교착 방지: 전투 적이 없고 장물아비가 전원 이탈하면 즉시 클리어한다
- 낙사 없음: 추격 중 낙하는 하단 우회(1막 규칙)이며 비용은 이탈 게이지 손해다

### A.8 재사용과 신규, 크로스 문서

- 재사용: 장물아비 조형과 강탈 연출, 웃돈 반환(ENEMIES 5.3). 도깨비불 발판(DESIGN_ACT1 3장). 창고, 항아리, 짐수레(DESIGN_ACT1 2.6). 이벤트방 템플릿(추격 코스 지원)
- 신규(소굴 전용): 진입 즉시 강탈과 도주/추격 상태머신, 이탈 게이지, 다수 개체 추격 UI, 떨이 유물 지급 훅. 기본 유닛은 공격형 상주(ENEMIES 5.3)이므로 소굴의 도주/추격은 소굴 전용이다
- 크로스 문서 확인 필요
  - ENEMIES 5.3 기본 장물아비는 플레이어 표적 공격형(피격 시 강탈)으로 확정되었다 (2026-07-25, D2-2). 소굴은 그 위에 다수 출현과 진입 즉시 강탈, 방 밖 도주 추격 회수를 얹은 소굴 전용 변형이다
  - RELICS.md 4장 획득처 표는 유물 소스로 "이벤트 P 결과"만 명시한다. 이 N 이벤트가 떨이 유물을 주므로 "이벤트 N(장물아비 소굴, 떨이 한정)" 행 추가가 필요하다(유물 세션 D2-4에서 반영 권장)

### B.0 공통 기반과 페어 관계

- 좌판 기반(DESIGN_ACT1 2.6): 진열대 1타일 발판 겸 엄폐, 파괴 가능 등급. 파괴 시 진열품 드랍(엽전, 소모품)과 주변 도깨비 어그로. 변형 3종(과실, 유기, 잡화). 거리형 전투방에 3~6기
- 두 이벤트 모두 전투형, 좌판 거리 테마 우선
- 관통 축: "이 방에서 좌판을 부술까." 대목은 파괴를 유혹(보상 상향), 상인회는 파괴를 억제(추가 전투). 좌판 파괴를 매 방 다르게 판단하는 선택으로 만든다(1막 정체성)
- 공존과 판별 (2026-07-25 결정, 기존 "상호 배타 권장" 대체)
  - 한 런에 둘 다 등장 가능하다. 이벤트 노드는 하나로만 확정되므로 같은 노드에 두 규칙이 겹치는 일은 없다
  - 판별 신호로 파괴 결정을 읽게 한다: (1) 노드 맵 P/N 표식(대목 좋음, 상인회 나쁨), (2) 방 내 시각 신호 - 대목은 좌판이 빽빽하고 드랍이 반짝이며 호객, 상인회는 성난 상인 도깨비가 좌판을 지키며 노려본다
  - "방을 읽고 부술지 정한다"는 스킬을 의도한다. 상호 배타 강제는 두지 않는다(생성기 단순화)

### B.1 야시장 대목 (P3, +20, 자동, 전투형)

- 트리거: 자동. 진입 즉시 방 상태 전환
- 전개: 좌판 밀도 2배(방 크기별 상한), 파괴 드랍 대폭 상향. 좌판 파괴 어그로 규칙은 유지한다. 단, 놋대야 등 규칙 개조 유물을 보유하면 유물 규칙이 우선한다 (RELICS 6.2 9번, 2026-08-05 D6 확정: 유물 우선)
- 결과: 부수면 대량 엽전과 소모품, 대신 어그로. "언제 부술지" 타이밍 게임이 남는다
- 파라미터(export): stall_density_mult 2.0, drop_bonus_mult 2~3(초안), aggro_on_break 유지
- 순점수 +20: 전투 부담 위에 큰 경제 이득. 큰 값 아님 (2026-07-27 점수 축소로 +30에서 하향)
- 상호작용: 놋대야 유물(RELICS 9, 좌판 파괴 시 어그로 대신 경직)과 강한 시너지(안전 대량 파밍). 장물 보따리 유물(RELICS 12, 장물아비 출현 증가)이면 늘어난 드랍을 노리는 장물아비가 붙는다

### B.2 성난 상인회 (N4, -20, 조건부, 전투형)

- 트리거: 조건부. 좌판을 부술 때만 발동한다. 안 부수면 평범한 전투로 회피 가능
- 전개: 좌판 파괴 시 즉시 추가 웨이브. 파괴가 쌓이면 웨이브가 누적된다(상한 있음)
- 결과: 파괴는 드랍과 추가 전투. 파괴 이득과 추가 전투 위험의 트레이드오프
- 파라미터(export): wave_on_break 파괴당 1~2(초안), wave_cap 누적 상한(초안), trigger_mode 파괴당 소환 또는 첫 파괴만(M2 체감 후 택1)
- 순점수 -20: 조건부라 회피 가능. 기본 전투(-20) 수준 유지
- 상호작용: 놋대야 유물은 어그로만 경직으로 바꿀 뿐 성난 상인회의 추가 웨이브 트리거는 막지 못한다(어그로와 웨이브는 별개 규칙). 놋대야로도 상인회 방은 여전히 위험하다

### B.3 상태 흐름 (공통)

1. 진입: 노드 P/N 표식. 방 내 판별 신호로 대목과 상인회를 구분(B.0). 대목은 즉시 밀도와 드랍 상향, 상인회는 성난 상인 배치
2. 전투와 판단: 웨이브 진행 중 좌판 파괴 여부를 판단한다. 대목은 부수면 대량 드랍과 어그로, 상인회는 부수면 드랍과 추가 웨이브(안 부수면 위험 없음)
3. 클리어: 웨이브 정리 시 종료. 상인회는 파괴로 늘어난 웨이브까지 정리해야 클리어
4. 보상: 대목은 파괴 드랍이 보상의 핵심. 상인회는 일반 전투 보상과 파괴분 드랍

### B.4 UI와 UX (색 채널 준수)

- 노드: P(대목)와 N(상인회) 극성 표식. 적색과 청록 금지
- 방 내 판별: 대목은 좌판 반짝임과 호객 연출, 상인회는 좌판을 지키는 성난 상인 도깨비와 노려보는 시선. 첫 좌판 접근 시 상인회는 경고 연출(부수면 덤빈다)
- 파괴 피드백: 드랍량과 어그로 또는 웨이브 발생을 명확히. 상인회 웨이브는 등장 방향 예고
